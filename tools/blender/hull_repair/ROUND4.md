# Pyre-Barge round 4, issue 146

Double-click **RUN_PYRE_ROUND4.bat**. It queues GPU lane A and uses the PC timeout runner, which waits while Ryan plays. It uses the installed ComfyUI Python and models, Blender 4.5.14, Godot 4.7.2 and Node 22. There are no downloads or paid services.

The results go to `docs/shots/ship_pipeline/pyre_round4/` and `Downloads\voidsworn_test\board\issue-146\shots`. Full PNG captures, candidate reference images and the selected runs' prompts and histories are retained in the issue folder. The final self-contained GLBs, including the native raw generation, are copied to its `models` subfolder. Working meshes, bakes, `.blend` files, import caches, logs and private saves stay in `%TEMP%\voidsworn_issue146`. Shipping assets and player settings are never replaced.

The worker phases are `reference`, `views`, `mesh`, `build`, `capture`, `game`, `checks` and `sheets`. The batch forwards these options, for example `RUN_PYRE_ROUND4.bat --phase capture`. Build and capture accept `--route V1`, `V2`, `V3` or `Raw`. A route capture writes its own measurements and does not replace the final all-route measurement file. `--work` must name a folder inside TEMP.

The default run performs all phases. Reference candidates are cached by name so an interruption does not throw away completed model work. Delete no experiment files to retry a stage: use a fresh TEMP work folder for a new complete experiment. The retained run's prompts, hashes and candidate selection are the reproducibility record; local diffusion models can produce small differences on a later run.

`round4_reference.py` makes new Qwen references from renders of the packed game ship. The faction pack supplies the prompt and negative. A targeted edit removes the first candidate's naval bow and adds dishes, claws, chains and rocket clusters. Multiple-reference edits repeated a camera, so the retained side, front and top use a separate camera-LoRA pass. Background preparation removes disconnected artifacts, not ship pixels. Pixal3D receives the four selected shape views on black with one shared canvas scale. Its installed maximum 2048 shape cascade is retained, then its native GPU QEM decimator targets 300,000 faces without a remesh. A 4096-pixel tangent normal bake records the fine geometry.

`round4_build.py` rebuilds issue 129 stage 5 in a private folder for V1. It replaces its trim materials with geometry-driven PBR and adds thin trophy markings and lights. V2 uses the new generation, native decimation and normal bake. The high-pass operation is `normalize(flat + gain * (deviation - blur(deviation)))`, where `flat=(0,0,1)` and `deviation=normalize(raw)-flat`. The computation uses float32, with PNG inputs and outputs. It does not claim to flatten geometry.

`round4_hand.py` builds V3 from a manually traced section drawing of the new reference. It never opens today's AI mesh. It adds open engine bells, dense forward rocket racks, mounted gun pairs, dishes, scoops, articulated claws, real chain links, radiators, pressure cells, service banks, overlapping plate stacks, pipes and two passes of the established `hs/detail_lib.py`. The starting kit follows the c19 mount, bevel and detail conventions. Primary and static kit geometry merge at export.

`round4_material.py` supplies the same material recipe to all three: soot and rust plates, worn trophy colours, short-distance AO grime, curvature and short-radius bevel wear, position-based scorch, local CC0 ambientCG PaintedMetal004 photo grain and roughness, plus red lamps and hot engine throats. Unique UV bakes replace overlapping trim paint. No reference art, AI albedo or rendered light is projected into the albedo. The normal bake is combined with the procedural micro-normal only on V2.

`round4_raw.py` streams all native generated triangles to a neutral display mesh. It applies a uniform presentation scale and axis transform, supplies outward normals and corrects inward winding if needed. It does not simplify, remesh or remove faces. The original generated GLB remains untouched.

`round4_probe.gd` reuses the earlier studio, real G4 lights and benchmark loop. Every route has the same cameras, 41.6 game-unit length, Forward+, 1920x1080, MSAA 4x, mipmapped compressed maps, 100 warm-up frames and 360 measured frames. The twenty ships share one mesh and maps in a non-overlapping 5 by 4 layout. These figures measure isolated rendering, not a whole battle, 4K or twenty distinct assets. The raw and filtered normal proof uses one measured side panel, with the same head-on and grazing cameras.

The actual-game phase copies this checkout's game code and the live build's generated resources into TEMP, isolates APPDATA, and substitutes the prototypes only in memory. It captures the board, HUD, ShipView and game lighting. The final verifier checks measured counts, reimports, source hashes, maps, gun directions, mount contacts, length, capture dimensions and unchanged shipping inputs. The human nine-cell verdicts remain in the report. Passing the experiment checks is not shipping approval.
