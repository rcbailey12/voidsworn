# Claude game dev skills and agent tooling for Opus

For Opus (Claude), who builds ship hulls and effects for a Babylon.js hex fleet tactics game on a Windows PC (PowerShell 5.1, RTX 5080) from Blender assets. The question this section answers: what current Claude tooling actually changes how Opus works, as opposed to what merely sounds impressive. The short version: the skills format is real and should be adopted immediately, the official Blender MCP server is the single biggest capability jump, and the process patterns worth stealing are screenshot evidence, a blocking validator, and a converge step.

## 1. Agent Skills: the format, and how to write one for this project

A Claude Agent Skill is a folder containing a SKILL.md file: YAML frontmatter with a name and a description, then Markdown instructions, plus optional scripts, templates and reference files. The format follows the Agent Skills open standard, documented at agentskills.io, and Claude Code extends it with invocation control, subagent execution and dynamic context injection. The official docs live at https://code.claude.com/docs/en/skills.

The property that makes skills worth adopting is progressive disclosure. At session start, only each skill's name and description sit in context. The full body loads only when the model judges the skill relevant, or when the user invokes it by name with a slash command. Reference material costs almost nothing until it is needed, which is exactly the problem this project's documentation has: roughly 52,000 words of design material that no session should load whole. Facts belong in CLAUDE.md because it loads every session. Procedures belong in skills because the body loads only when used.

Frontmatter fields that matter here: `name` (lowercase, hyphens, up to 64 characters), `description` (non-empty, up to 1,024 characters, and it must say both what the skill does and when to use it, because the description is the trigger), plus Claude Code extensions such as `allowed-tools`, `argument-hint`, `user-invocable`, `context: fork` (run the skill in an isolated subagent), `paths` (activate only when matching files are touched), and `disable-model-invocation` (human-invoked only, the right choice for anything that pushes or publishes).

Where skills live decides who gets them. Project skills go in `.claude/skills/<name>/` inside the repo and are committed so the whole team gets them. Personal skills go in `~/.claude/skills/`. Plugin skills ship inside a plugin. A skill folder can also be turned into a plugin by adding `.claude-plugin/plugin.json`, which lets it carry its own agents, hooks and MCP servers.

Anthropic's own example skills live at https://github.com/anthropics/skills (about 183,000 stars at last check). Most are Apache 2.0, but the document skills (docx, pdf, pptx, xlsx) are source-available, not open source, and the repo warns that the examples are demonstrations, not production guarantees. The repo also ships a skill template and the Agent Skills specification itself, which is the right starting point for writing project skills. Install is via `/plugin marketplace add anthropics/skills` in Claude Code, and the `skill-creator` skill in that repo builds new skills with no code.

Three skills this project should have, in priority order:

**ship-kit.** Description trigger: use when building, dressing or exporting any hull, or when touching the kit pipeline. Body: the landmark-driven template kit rules, the per-ship manifest format, the glTF export survival checklist (from the tool guides), the triangle budgets per tier, the silhouette sheet acceptance step, and the Pixel stress gate before hull 6. Reference files: the ship kit work order and the Blender section of the tool guides. This is the single highest value skill, because it turns a 14,000 word tool guide into a procedure that loads only on hull work.

**screenshot-verdict.** Description trigger: use whenever a change affects anything the player sees. Body: launch the game, capture the beauty corner scene and the battle view from fixed camera angles, compare against the acceptance image, list exactly what differs, and never close a visual story without a retained screenshot. This borrows the Game Studios rule described in section 2, and it is the direct answer to the review thread's standing problem: CSS arithmetic findings that were never confirmed on a real device.

**playtest-and-balance.** Description trigger: use after any rules, balance or content change. Body: run the sim harness and the checkpack, run the campaign leg, compare the new numbers against the last balance reference, and report only deltas with the mode that produced them. This makes the existing compute folder a procedure instead of a pile of files.

Claude Code also ships bundled skills worth knowing: `/doctor` (a setup checkup that diagnoses installation, extensions, CLAUDE.md duplication and permissions, and can migrate always-loaded guidance into skills), `/run` and `/verify` (launch and drive the app, then confirm a change against the running app rather than tests alone), and `/run-skill-generator` (records the launch recipe once as a per-project skill so later sessions follow it instead of rediscovering it). When a project skill named `verify` exists, Claude Code's commit instructions tell it to run that skill right before each commit. That is the mechanism that turns the checkpack into a gate without anyone remembering to run it.

## 2. Community skill collections for game development

The ecosystem exploded in 2025 and 2026, and most of it is noise. The curated entry points that are actually useful:

**awesome-claude-code** (reported at 35,000 plus stars) is the largest collection of skills, hooks, slash commands and agent orchestrators for Claude Code. **awesome-agent-skills by VoltAgent** (reported at 13,000 plus stars) is cross-platform, working with Claude Code, Codex, Gemini CLI and Cursor. **awesomeclaude.ai** is a directory of 241 skills with install commands, merging the official Anthropic skills with the two largest community lists and removing duplicates and dead links. Install methods are consistent across all three: a plugin marketplace entry, `npx skills` (an open CLI that copies a skill into the right folder), or copying the SKILL.md folder by hand into `.claude/skills/` for one project or `~/.claude/skills/` for every project. Licence note: the lists themselves are free to browse, but every skill inside keeps its own licence, and bulk lists include mass-generated entries. Prefer skills with a named author, a changelog and a test story over star count alone.

**Claude-Code-Game-Studios by Donchitos** (https://github.com/Donchitos/Claude-Code-Game-Studios, MIT, about 27,000 stars, created February 2026) is the one game dev collection worth studying in full. It turns a Claude Code session into a studio hierarchy: 49 agents (directors, department leads, specialists), 74 skills, 15 hooks, 14 path-scoped rules and 62 document templates. Engine specialists exist for Godot 4, Unity and Unreal Engine 5, but not for Babylon.js or for a browser game, so it cannot be adopted wholesale for this project. What should be stolen from it:

- The skill set that maps directly onto this project's needs: `/asset-audit`, `/balance-check`, `/playtest-report`, `/perf-profile`, `/scope-check`, `/gate-check`, `/design-review`, `/code-review`, plus team orchestration skills (`/team-combat`, `/team-polish`, `/team-audio`) that coordinate several agents on one feature.
- The screenshot evidence rule, stated plainly in its README: a story that changes anything the player sees is not closed until the game has been launched, observed, and a screenshot retained as evidence. A parse check is not a run. This is the rule the visual work here has been missing.
- The hooks: automated validation on commits, pushes, asset changes and design-doc reads, with graceful failure when optional tools are missing. One deliberate exception is instructive: a commit that stages data JSON is blocked when there is no Python to validate it. That is the data checker pattern, enforced rather than suggested.
- The honesty in its own measurement: four games built from one brief at different rigor levels, with the `standard` build (30 documents before its first line of code) ranked last by blind reviewers and a human playtest. The extra documents bought traceability, not a better game. The template's default is therefore `minimal` rigor, raised only when the project grows. For Opus, that argues against turning the design pack into a documentation gate: the docs are reference, the screenshot and the sim are the gate.

Practical costs: Claude Code itself (npm install, Node.js 22 plus), Git, Python 3 (the template reads its project.yaml with Python, and without it every setting silently falls back to default), Bash (on Windows, Git for Windows), and optionally jq for hook validation. No engine specialist for Babylon.js means the template's engine setup skill does not apply; the studio structure and the QA skills do.

One more named skill worth a look, reported in community lists: **superpowers by obra**, whose brainstorm skill forces the agent to ask hard questions before acting, with a claimed reduction in revision rounds. Treat that claim as unmeasured marketing, but the pattern (a skill that asks the scope questions the repo's own AGENTS.md already demands, 3 to 5 plain-language multiple-choice questions before anything bigger than a quick fix) is exactly right for this project, where scope creep is the documented failure mode.

## 3. MCP servers: hands inside the tools

MCP (Model Context Protocol) servers give a model tools inside an application, instead of the model writing a script for a human to paste in and run. For this project, the Blender side is the whole story.

**The official Blender Lab MCP server** (https://www.blender.org/lab/mcp-server/) is the Blender Foundation's own bridge to Blender's Python API, announced April 28, 2026. It requires Blender 5.1 or newer. Installation is an add-on plus a server: drag the install link into Blender twice (once for the Blender Lab repository, once for the add-on itself), or download the add-on zip and install from disk, then connect any MCP client. It also ships as an `.mcpb` bundle for newer clients. What it does, per its own page: natural-language access to the Python API, documentation lookup, scene analysis (its worked example finds polygon-count outliers relative to on-screen size in the Classroom benchmark file), data-block renaming and auditing, geometry node documentation, and a checklist verifier (meshes must be manifold, all objects must have materials, naming must follow convention, no absolute paths). A secondary comparison reports it as GPL-3.0-or-later, v1.0.0 released April 27, 2026, v1.0.3 current as of September 2026, but the official page itself does not state a licence in the sections reviewed, so treat the licence as unconfirmed from primary sources.

**The Claude Blender connector** (Claude for Creative Work, announced April 28, 2026 alongside connectors for Adobe, Autodesk Fusion, Ableton, Splice, SketchUp, Affinity and Resolume) is Anthropic's Claude Desktop route to that same official server. It needs Blender 5.1 or newer and Claude Desktop, with read, write and delete permissions for scene objects configured separately. In practice it lets Claude analyze and debug scenes, build custom scripts, and batch-apply changes across objects. The funding footnote is worth knowing and not worth over-reading: Anthropic initially announced Development Fund patron status, then downgraded it to a one-time donation after community objections, and the connector itself is unaffected because it is built on the open MCP standard and works with any MCP client, not just Claude.

**The community MCP for Blender** (https://github.com/ahujasid/blender-mcp, now renamed mcp-for-blender, MIT, about 29,500 stars) predates the official server and is still the most widely installed. It works with Blender 3.0 and up, which matters if the PC's Blender is older than 5.1. Architecture: a Blender add-on listening on localhost port 9876, plus a small MCP server started with `uvx blender-mcp`, giving Claude tools to create, modify and delete objects, apply materials, inspect the scene, run arbitrary Python, and render. It also bundles third-party integrations the official server does not: Poly Haven assets, Sketchfab search, and Hyper3D Rodin 3D generation. That breadth is also its risk: arbitrary Python execution inside Blender, on the machine that holds the project, with no sandbox in the default setup.

Other community Blender servers, all from a single October 2026 comparison and therefore secondhand: RFingAdam/mcp-blender (218 tools across modeling, materials, sculpting, animation, AI generation, with a render-analyze-refine loop), PoBruno/mcp-blender-agent (about 216 typed tools built around deterministic, validated operations instead of improvised Python), djeada/blender-mcp-server (27 tools across 7 namespaces, with a shared secret token file and a start script that opens Blender plus a connected Claude Code session), loonghao/dcc-mcp-blender (part of a DCC family, ships an Agent Skill), and StraySpark's production-oriented server (code execution denied by default, path jails, an audit log, 22 tools, Blender 5.1 plus). The pattern to copy from the last two is not their tool count but their posture: typed, validated operations and denied-by-default execution beat a bigger tool surface for production work. The desktop app alternative is 3D-Agent (Blender 4.2 plus, no MCP setup, no API key), which trades the open MCP route for a packaged agent.

Security, stated plainly because it decides the setup: the official Blender Lab page warns that the server executes model-written code without guards and recommends a virtual machine or a machine without sensitive data. On this PC, that means the Blender MCP runs against the project folder only, never against the whole machine, and Opus never gets it pointed at a Blender install that can reach credentials. The djeada variant's token file (mode 0600) is the minimum pattern for any server left running.

**Unreal, Unity and Godot MCP servers** are the pattern for what an engine bridge looks like, and they matter here as a template, not as tools to install. IvanMurzak/Unreal-MCP (beta, 61 built-in tools across 7 families, C++ editor plugin plus a .NET sidecar process because Unreal's editor is C++, with a hosted backend at ai-game.dev or a self-hosted GameDev-MCP-Server) is explicitly the Unreal counterpart of Unity-MCP and Godot-MCP, which share one engine-agnostic server. The lesson for Babylon.js: an engine bridge is a plugin inside the engine plus a small server outside it, exposing inspect, edit, run and screenshot tools. No first-class Babylon.js MCP exists. A directory listing (https://glama.ai/mcp/servers/integrations/babylon-js) shows only small community servers: one for live scene control graded low on quality and maintenance, and one docs and scaffolding server covering 29 engines (MIT) that is a documentation aid, not a scene bridge. Treat both as unproven. The practical Babylon.js equivalent is not an MCP server at all: it is the browser screenshot loop in section 4 plus a tiny local tool server over the game's own debug hooks (launch, capture, run sim, dump state), which is a weekend of work and avoids depending on an unmaintained listing.

## 4. Agent workflows actually practiced in 2025 and 2026

**Screenshot-driven iteration loops.** The cleanest documented example is a 3D modeling loop built by Dave Snyder and written up in March 2026 (https://abit.ee/en/artificial-intelligence/claude-code-3d-modelling-playwright-ai-agent-anthropic-autonomous-loop-web-development-en): Claude Code was given Playwright commands for a virtual camera (capture from an angle, zoom, place red spheres as position markers), and the loop runs modify geometry, generate the model, render from multiple angles, verify against the goal, repeat, with no human in the loop. The manual version (human screenshots after every change) worked but was painfully slow; the autonomous loop is what made it scale. Google's Antigravity (launched November 2025, public preview, free) builds the same loop into the platform: browser actuation, screenshots and recordings as verifiable artifacts, Gemini 3 Pro or Claude Sonnet 4.5 as the model. Flag it honestly: cloud-only processing, preview instability, and scant evidence of shipped games built primarily in it. For this project, the loop is already half built: the game runs in a browser, the tool guides describe the capture workflow, and the missing piece is only the camera commands and the verdict step.

**A separate, blocking validator.** A game factory post from 2026 (https://www.bassimeledath.com/blog/game-factory) documents the failure mode that matters most: a creator agent that self-reports PASS without running the validator, because nothing forced it to. The fix was structural, not prompt-based: validation is a separate agent, validation is blocking (the creator cannot proceed until the validator returns), and failures return to the creator with specific issues for up to N attempts. The author notes Anthropic's engineering team found the same thing, that models are terrible at evaluating their own work. For Opus, that maps directly onto the role split already in place: Opus builds, a separate check (the checkpack, the sim harness, the screenshot verdict) runs, and the result blocks the commit. Advisory checks get skipped; blocking checks get obeyed.

**Spec-driven development.** GitHub Spec Kit (https://github.com/github/spec-kit, MIT, version 1.0 August 2026) formalizes the workflow as Specify, Plan, Tasks, Implement, Converge, with a constitution phase (project-wide invariants every feature inherits) and an optional clarify phase (the agent asks the human questions before committing to an approach). It supports 30 plus agents including Claude Code, and brownfield projects, not just greenfield ones. The converge step, added June 2026, is the part worth adopting: it re-checks the code against the spec and repeats implementation until the two match. This project's constitution already exists in everything but name: the repo's AGENTS.md and REVIEW_PROTOCOL.md, the standing rulings, and the ship kit work order. What is missing is the converge step as a named, blocking phase, and that is a one-paragraph addition to the review protocol, not a new tool.

**Subagent orchestration for asset batches.** The Game Studios template's team skills (`/team-combat`, `/team-polish`, `/team-audio`) are the pattern: one coordinator, several specialists, one feature, with escalation paths. For the 36-hull queue, the shape is one hull per subagent batch against the same kit skill and manifest format, with the coordinator running the silhouette sheet and the Pixel stress gate. The failure mode to guard is the one the template's own measurement found: process that produces documents instead of assets. The batch coordinator's output is rendered hulls and a screenshot sheet, not a status report.

**Hooks as guardrails.** Claude Code hooks bind shell commands to lifecycle events in settings, and they fire unconditionally: the model has no say in whether they run. The events that matter here are PreToolUse (validate or block before a tool executes, exit code 2 blocks the call and the hook's stderr becomes the reason), PostToolUse (log, format, or trigger downstream checks), and Stop (run a final check when the agent finishes). The documented pattern for a pre-commit gate is a PreToolUse hook on Bash that matches `git commit` and runs the checks, blocking the commit on failure. For this project, the hook set writes itself: block commits that stage data JSON without a passing reference check, run the checkpack on any commit touching game code, and run the golden-save compatibility test on any commit touching content ids. The Game Studios template's note applies: hooks fail gracefully when optional tools are missing, except the deliberate data JSON exception, which is the right default.

## 5. Hype versus real, stated plainly

Real and adoptable now: the Agent Skills format and the official docs, the official Blender Lab MCP server (with the version and VM caveats), the community MCP for Blender for older Blender installs, Spec Kit's converge step, hooks as blocking gates, screenshot loops, and the Game Studios template's QA skills and evidence rule (not the whole template).

Unproven or exaggerated: one-shot AAA game claims (a 2026 analysis notes the genre in question is among the most heavily documented in existence, which makes "built from scratch" hard to credit, and that no contamination check was published); Antigravity as a game dev platform (promising loop, cloud-only, preview stage, no shipped-game evidence yet); paid agent products sold as studio replacements (Ziva for Unreal is enterprise engagement, scoped per studio, not a download); bulk skill repositories boasting tens of thousands of entries (most are mass-generated, and the useful signal is a named author plus a test story); and any Babylon.js MCP listing (thin, low maintenance grades, no scene bridge).

Costs to be honest about: Claude Code itself needs a paid plan for sustained use, Blender is free, the MCP servers above are free and open source, Spec Kit is MIT, the Game Studios template is MIT, and the paid surface is the model subscription plus any hosted generation (Rodin, Sketchfab downloads) the community server bundles. Nothing here requires a new paid product to start; the Blender MCP trial costs an afternoon and a VM-shaped caution.

## What to do first

1. Write the three project skills (ship-kit, screenshot-verdict, playtest-and-balance) into `.claude/skills/` in the repo, following the official template, and commit them. This costs nothing and pays on every session after.
2. Trial the official Blender Lab MCP server on a scratch hull, on the condition that the PC's Blender is 5.1 or newer and the server runs against the project folder only. If Blender is older, trial the community MCP for Blender instead.
3. Add the two process fixes that need no tooling: the screenshot evidence rule (no visual story closes without a retained screenshot) and the converge step (re-check code against spec before commit), enforced by a PreToolUse hook that blocks data JSON commits without a passing reference check.
