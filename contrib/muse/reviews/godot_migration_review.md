# Godot migration review, synthesis, 2026-10-26

Chair synthesis of four blind inputs against the same evidence pack (evidence_pack_migration.md, godot/ on main as of Oct 26, 2026): DeepSeek, Qwen (Qwen3.8-Max, both gates passed), Argon (Gemini 4 Argon, Thinking level High, verified in two places), and Rey's own audit, which read the fetched sources directly. Legs filed at contrib/deepseek/reviews/migration_review_deepseek_2026_10_26.md, contrib/qwen/reviews/migration_review_qwen_2026_10_26.md, contrib/gemini/reviews/migration_review_gemini_2026_10_26.md, and contrib/muse/reviews/godot_migration_review_rey.md. Scope: all Godot work except fx visuals and flash, campaign screen information design, story content, and accessibility settings, except structural intersections. Code claims in this synthesis are observations for Opus to confirm; Opus owns code truth.

Overall verdict: SOUND WITH RISKS. The hard part of the migration is done well: exact-double rules parity against a pinned oracle, checksum-locked generated tables in both streams, total RNG discipline inside the rules, 30-run campaign parity with save and reload cycles, bot error counting and hang diagnostics. What remains is a short list of shell, threading, build and honesty fixes. Three items are high severity, and only one of them (the unseeded campaign stream) is player-visible today.

## Chair corrections applied across all legs

Three items in the pack and the external legs needed correcting before merging. The synthesis follows the corrected versions everywhere below.

1. Warning suppression: 6 of 17, not 17. rules.gd:11, jsm.gd:13 and battle_api.gd:6 each open @warning_ignore_start listing 17 classes, but the Rey audit's direct read of project.godot shows only 6 of those classes are set to warn at project level (unsafe_property_access, unsafe_method_access, unsafe_call_argument, integer_division, narrowing_conversion, return_value_discarded); the other 11 are project-ignore anyway. The finding stands and is sharper for the correction: the suppression silences exactly the classes the project deliberately left on, and two of them (integer_division, narrowing_conversion) are the documented JS-port trap categories. Scope the fix to those six, not seventeen.

2. Oracle sync: a manual step IS documented; an automated check is not. All three external legs repeat the pack claim that neither oracle README documents a sync step, and DeepSeek ranks it second-highest severity on that basis. The Rey audit read both READMEs directly: both pin commit c7b1a78 and both document a manual "Catching up" re-copy step. The real defect is narrower: nothing automatically checks that the two vendored copies (battle.js, core.js, data.js in godot/rules/test/oracle/ and godot/campaign/test/oracle/) match each other, so a one-sided manual re-pin would drift silently. Severity drops; the chair does not adopt DeepSeek's number 2 ranking for it. The fix (a hash compare in the existing parity runners) stays cheap and worth it.

3. CUT/SOLID hash coverage: DOCUMENT DIVERGENCE, carried as UNSURE for Opus to settle. The pack and all three external legs state that the canonical hash excludes CUT and SOLID module state, so a terrain-state bug could pass parity silently. The Rey audit flags that rules_test_README.md:34 describes each golden record as holding state including "the board cut-outs, the hexes that block sight" plus a SHA-256 of that state. The golden writer (golden.js, parity_main.gd) was not fetched by any input, so the chair cannot settle which document is right. The earlier sprint Job A synthesis found the same exclusion from code reading, which supports the pack, but on the evidence in this review the item is a divergence, not a settled defect. One of the two documents is wrong; if the pack is right, a terrain-state bug class is invisible to parity and a scenario exercising terrain state into the hash belongs before cutover. Opus: one line settles this.

## Per-area verdicts

Chair bar: an area is SOUND only if a future ordinary change (a new caller, a re-pin, a packaging step, a mid-write crash) cannot silently produce wrong behaviour that no existing test would catch.

- Rules port and parity: SOUND WITH RISKS. Exact-double compare with no tolerance, SHA-256 over canonical state at every action point, scenarios s1-s23 across all 8 fight types plus a 200-battle sweep, zero uses of Godot's global RNG in the ported files. Risks are at the edges: the unseeded shell stream (below), the five silent maths edges, and the CUT/SOLID divergence above.
- Threading and shared state: NEEDS WORK. Safe today by a stated scene convention, not by API enforcement. step() is the only locked method in battle_api.gd; threat_map() runs eval_begin() on a worker thread and clears the six shared eval caches over live units; jsm.gd:15 keeps one static 8-byte scratch buffer behind every float-word conversion in the process. Single-threaded parity cannot see any of this.
- Campaign logic and saves: SOUND WITH RISKS. The single-entry act() contract, IEEE-hex float encoding, table checksum, and keep-the-sound-half loader are strong. The one clear defect is the non-atomic write (copy to .bak, then overwrite in place).
- Shell and glue: SOUND WITH RISKS. Error counting, hang diagnostics and the two-frame static cleanup are genuinely good. Held back by silent degradation: ResourceLoader.exists soft dependencies can ship the facts-and-buttons fallback campaign UI with no error anywhere, fx_stub.gd still runs beside the real fx, and NOT PORTED clears and plays a partially computed batch in live battles.
- Data duplication and drift: NEEDS WORK on guarding, not on current correctness. No leg found a live divergence. The generated tables are checksum-locked; the hand-copied render and world constants (FAC3D, AI_HULLS, CLS_LEN, FINISH, BIOMES, ROCKS, PLANETS) and the manually synced oracles have no comparison at all. Argon would generate the constants; Rey and Qwen prefer a diff check; the chair prefers the diff check (drift becomes detected, and a cosmetic mismatch cannot block the game the way a checksum refusal on a colour table would).
- Asset pipeline and build: NEEDS WORK for reproducibility. godot/gen/ has zero files on main, the A4 ship sources live off-repo on the build PC, sky and asteroid inputs fall back to contrib/opus/enginetest/, freshness is keyed to a hand-bumped GEN_VERSION plus file existence only, and ship_view.gd falls back silently to a plain BoxMesh. The PC workflow functions; a clean checkout cannot build the shippable game.
- Music and portraits plumbing: SOUND code, NEEDS WORK state reporting. Both subsystems are well built and headless-safe. But godot/music/ holds only README.md, music_player.gd and its test: music.json, tracks/*.ogg and CREDITS.md do not exist, music_check.gd cannot pass as written, and FEATURES.md marks Music done. This also keeps 26c Job 5 (music licences) blocked; there is nothing to check yet.
- Performance shape, test gaps, documentation drift: SOUND WITH RISKS. view() rebuilds the full view per call and ui_info() computes per weapon against every living enemy without the eval_begin/eval_end caching its sibling methods use (Argon's arithmetic: 90 LOS calls where 15 would do, on a 6-weapon ship facing 15 enemies). No test covers shell startup seeding, export contents, gen/ freshness, hand-copied constants, save truncation, or threading overlap. Documentation-versus-tree drift is a class, not a nit: music (above), the stale DRAWN column in FEATURES.md, the export path disagreement, and possibly the CUT/SOLID README line are four instances of docs written at landing time and never re-checked against the tree.

## Bugs ranked by severity (merged)

1. [High] Campaign RNG never seeded in the shipped shell. jsm.gd:52 starts the one shared mulberry32 stream at 0; newRun (campaign.gd:942) draws foes, patrons, captain names, starting relic, the sector 1 map, node seeds and the Nemesis with no reseed anywhere in main.gd, title.gd, campaign_host.gd or story.gd (the no-seed claim for main.gd rests on the pack's grep; the other three files were read directly and contain zero JSM references). The standalone campaign scene seeds from the wall clock (campaign_scene.gd:27), and the browser does too, so the shell is the odd one out. Result: identical first-run content on every launch and install until player choices desync the draw count. No test can catch it, because parity and bots seed explicitly. Fix is one line plus a continued-run decision (open question 2).
2. [High] Threading by convention. battle_api.gd step() is the only locked entry point; view() runs on the worker after step() unlocks; threat_map() mutates the shared eval caches from a worker; jsm.gd's static _pb buffer is shared by every thread converting a float. Four legs agree on the mechanism; actual overlap in current play is INFERRED, not observed. Companion risks: step() has no failure path if a runtime error aborts it while the mutex is held, and nothing documents how an in-flight worker task is drained when the player quits mid-battle (Argon cites the Godot docs: wait_for_task_completion must be called before freeing objects a task touches).
3. [High] The shippable game cannot be built from the repo alone. gen/ absent, A4 sources off-repo, sky/asteroid sources in a contrib scratch folder, freshness by version constant only, silent BoxMesh fallback. If the enginetest folder is cleaned up, two content inputs lose their sources silently.
4. [Medium] JSM unported maths edges return 0.0 (or 1.0 for cos) and play continues: jsm.gd:162, 225, 240, 317, 352. push_error only logs in a release build, so an extreme input becomes a wrong but plausible number. The rules layer has a proper NOT PORTED stop; the maths layer does not use it. Argon and DeepSeek note the remaining fdlibm branches are short (atan2 infinities, exp overflow/underflow) and portable now.
5. [Medium] NOT PORTED degrades in live play: battle.gd _think (about line 662) and _cmd (about line 674) record the error, clear R.not_ported, and play the partially computed batch. Right call mid-migration; before cutover the unported set must be proven empty or this becomes a hard stop.
6. [Medium] Export ships test content and lacks release metadata. export_presets.cfg:11 excludes only rules/test/* and audio/build/*, so campaign/test/ (about 516 KB of JS oracle plus Node harnesses) and music/test/ land in the .pck. Icon, file_version, product_version and codesign are empty, and the preset's export_path disagrees with FEATURES.md.
7. [Medium] Music content missing while docs claim it exists and FEATURES.md marks Music done (see per-area verdict). music_check.gd cannot pass as written.
8. [Low-Medium] view() returns arena and shMax by reference against its own read-only contract (battle_api.gd:104, 117 in the Argon copy's numbering). A renderer mutating what it is handed writes into live rules state, and compounds the threading risk.
9. [Low-Medium] Save and settings writes are not atomic. persist_save (campaign.gd:362-375) copies to .bak then overwrites in place; a mid-write crash loses the newest save step (the loader's fallback and keep-the-sound-half behaviour mitigate well). save_settings has no backup and no version field at all.
10. [Low-Medium] Soft-dependency silent degradation and the leftover fx stub. The fallback campaign UI can ship with zero errors logged; a present-but-unparseable script makes load().new() throw instead of falling back on some paths; fx_stub.gd (battle.gd:25) still preloads beside the real fx even though its own removal condition (godot/fx/API.md existing) has been met. Which cues each system owns is UNSURE.
11. [Low-Medium] Unguarded drift surfaces: dual vendored oracles with a documented manual re-copy but no automated cross-check (corrected item 2 above), and hand-copied render/world constants with no generation or comparison. No live divergence found; the first unmirrored JS-side change diverges silently.
12. [Unranked, UNSURE] CUT/SOLID parity coverage: either a parity blind spot or a wrong README line (corrected item 3 above). Ranked here only because it cannot be ranked until Opus settles which document is right.

## Refinements ranked by value per unit of effort

1. Seed JSM at shell startup from the wall clock (one line, matching campaign_scene.gd:27 and the browser), plus a startup test asserting the stream is non-zero after booting the main scene.
2. Make the JSM float conversion thread-local or local-array (one file, small diff), removing the shared _pb race class entirely.
3. Take the existing mutex in every public battle_api entry point, not just step(). The scene already serialises calls by flags, so this enforces current behaviour rather than redesigning it. Argon's variants worth weighing: a combined step_and_view() locked call, try_lock for hover previews so the UI never stalls, a debug concurrency assertion as the cheapest guard, and a cloned read-only state for threat_map() if contention ever shows. Also drain worker tasks with wait_for_task_completion on scene exit.
4. Expand export_presets.cfg exclude_filter to cover all test trees (rules/test/*, campaign/test/*, music/test/*, */test/*, audio/build/*), and add an export-content check on the built .pck that fails if any test path appears or gen/manifest.json is missing.
5. Narrow the three warning suppressions to drop the six project-warn classes, starting with integer_division and narrowing_conversion, fixing or individually suppressing what surfaces. campaign.gd lives with warnings on, which proves it is livable.
6. Port the remaining short fdlibm edge branches in jsm.gd (atan2 infinities, exp overflow/underflow) and make the rest hard stops rather than silent 0.0 returns.
7. Atomic save and settings writes: temp file, flush and close, rename over the target, keeping the .bak generation.
8. Duplicate arena and shMax in view() (two small copies per call).
9. A Node diff check for the hand-copied constants plus a byte-compare of the shared oracle files, run with the parity scripts. Qwen and Argon add the same shape for the wider drift class: a small tree-versus-docs hygiene check (doc-claimed files exist, oracle hashes match, preset exclusions present, truncated-save recovery).
10. Wrap ui_info()'s weapon loop in eval_begin/eval_end (under the mutex), and add a view()/ui_info() timing line at s23 scale to the existing timing report before anyone optimises blind.
11. A debug assertion in finish_battle for the B fields the campaign actually reads, and a startup smoke assertion in bot mode that the real campaign UI, real fx, story hook and music player all loaded rather than fell back.
12. Source hashes in the gen/ manifest so _current checks content, not just a version constant; move the sky and asteroids.json sources into a tracked repo folder and log loudly if any contrib fallback is ever used.
13. One line each in the determinism docs: parity proves sequential determinism only; audio randomness (sfx.gd's global randf/randi) is unseeded by design. Plus a settings version field at the next save-format touch.

## Alternative approaches (with trade-offs)

- PRNG: per-instance streams (rules and campaign each own an rng field, battle seeded from the node seed) vs the current process-global JSM stream (Argon). Kills the cross-system contamination class documented in port_notes.md, at the cost of a mechanical sweep of JSM.rnd() call sites and re-verifying whether campaign parity expects battle draws to advance the campaign stream. The chair does not recommend this now; the seeding fix plus the lock work closes the live defects, and the global stream matches the JS original parity is checked against.
- Threading: one dedicated rules thread with marshalled results (Rey) vs lock-everything plus thread-local buffer. The dedicated thread is cleanest long-term and kills the class permanently, but rewrites the scene's batch and animation flow mid-migration. Rejected for now; revisit only if a second concurrent caller appears.
- Render/world constants: full generation with checksum lock, like tables.json (Argon, Qwen) vs a diff check (Rey, chair). Generation makes drift impossible but puts presentational data on the game's critical path; a colour-table checksum refusal would block the game over a cosmetic. Prefer the diff check.
- Generated assets: track A4 sources in Git LFS and generate gen/ on build, with a mandatory pre-export check (Argon Alternative A, chair's preference) vs commit gen/ itself in Git LFS (Rey, Argon Alternative B). Committing gen/ makes clone-and-export work with zero build step but churns binaries on every generator change. Either is defensible; the current undocumented middle state (build depends on PC state no document fully lists) is not.
- Battle hand-off: a typed outcome summary from battle_api vs raw B with a schema check (Argon). The summary is cleaner but breaks direct JS-oracle parity unless mirrored in JS. Keep raw B plus the assertion (refinement 11).
- Status tracking: generate FEATURES.md's table from tree probes and test results (Argon) vs hand-edited. Generation costs about 40 lines and ends the drift class at its source; worth it if the doc keeps being used as a gate.
- Oracle after cutover: freeze the JS parity harness as a historical snapshot and make GDScript authoritative (Argon). Correct at cutover, wrong before it, while stream B still lands in JS first. Record it as a cutover decision, not a now action.

## Additions before cutover

1. Shell startup seeding, with the continued-run policy implemented and a startup test (bug 1).
2. Threading hardening: refinements 2 and 3, worker drain on exit, and one overlapping-call test (threat_map during a worker step), even if it only runs in bot mode. After cutover, race bugs have no browser build to bisect against.
3. Maths edges and NOT PORTED become hard stops in release builds, or the unported sets are proven empty by a sweep that exercises every push_error path.
4. The CUT/SOLID question answered in writing, and if the pack is right, terrain state exercised into the hash.
5. Export preset excludes all test trees, the export-content check runs on the built .pck, and the bot-mode smoke assertion proves the real UI, fx and story hook loaded.
6. Atomic save write. Save-loss reports land in the first week after cutover, when there is no other build to fall back on.
7. fx_stub retired (after its cue ownership is confirmed against the real fx) and core soft dependencies converted to hard loads or explicit CLI-gated fallbacks.

## Additions before Steam

1. Reproducible build from the repo alone: sky and asteroid sources in the repo, A4 sources in the repo (Git LFS) or behind a documented fetch step, source-hash freshness, and a one-page build recipe (Godot version, build_assets command, export preset) in one place.
2. Export metadata sorted: icon, file and product versions, company name, codesign, and the export path disagreement with FEATURES.md resolved.
3. Music content landed (music.json, tracks, CREDITS.md) with licences verified (unblocking 26c Job 5), or the docs corrected to say the player ships silent until it does. A silent game reads as a bug to a buyer.
4. Save corruption test: truncated and bit-flipped saves through load_save_text, asserting the backup path and keep-the-sound-half behaviour.
5. Frame-time budget for view() and ui_info() on 20-ship carrier boards across the Steam hardware range, and the FEATURES.md player-facing gaps closed (working graphics quality setting, temporal AA toggle, legend and command strip help, tenth onboarding tip, battle cut-ins).
