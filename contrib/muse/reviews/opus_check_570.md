## The Board's five questions

1. NO BOX POINTS: the service is clean. Every function in the attach service (fx_hull.gd, from the issue 370 banner to the end of the file) returns an authored point, a ray hit on the hull's triangles, a seen surface sample (itself a ray hit), the triangle-derived core, or an empty dictionary for a skip; the chair read the whole service and both legs traced it function by function. The box is used to aim rays and to score candidates, never returned. Callers: fx_ship's corner candidates only pick which jet to ask for (the placed point comes from hull.jet), ship_view's puffs route through jet_point per the report, fx's boarding reads board_origin, and the fx_weapons volley reads hull.guns. The disclosed exceptions stand as the worker stated them, with the chair's agreement: fx_ship.gd:568 is a torque arm (physics, not a placement), fx_weapons' to_c is a volley's aim and miss line (not an effect origin), fx_death.gd:1594 is a wreck spin pivot, and fx_ship.gd:1273, the damaged squadron's smoke ribbon at hull.c minus 0.2 of the length, is a real box-fraction origin that the report discloses and justifies (a wing of craft has no hull of its own). The Board should keep that one on the record as a named exception, which the report already does. One more, at NOTE grade: _find_core leaves core equal to the box centre when a hull has fewer than three faces or its volume and area both measure zero. core_point() already skips on a triangle-less hull, and no hull in the walked set comes near the case, but shield_centre() and direct hull.core readers would silently get the box centre on such a hull; worth a guard when the file is next touched. (Qwen's leg says the core is never the box centre; that sentence is wrong in this degenerate branch, and the chair's reading follows DeepSeek's.)
2. RULES UNCHANGED: sound. The battle change is one line adding "slot" (the rules fire event's own weapon index, null-guarded to -1) to the volley options. fx_weapons reads it once, into hull.guns; inside the service the slot only filters authored points and keys the muzzle-cycling offset. Nothing in the service writes to anything but hull-local bookkeeping (attach_counts, _attach_logged, _gun_turn). No rules file is in the PR. RULEBOOK 7.4's line, the look reads the rules and never feeds back, holds.
3. THE CHECK BITES: yes, on the evidence supplied. attach_check.gd measures each returned point's distance to the hull's triangles with 258 rays (an upper bound on the true distance, so a pass is sound and a failure is loud), at the export check's own tolerance of 0.012 of the length. The main-era run in the PR fails with 24 points off the hull across the ring and tower stand-ins (worst 6.74 units on the tower), and the PC run on the branch passes all 39 hulls (36 real ships plus the 3 stand-ins) with 0 failures and 0 skips; the chair parsed the PC JSON directly. The check is listed in godot_checks.txt (line 44), so it runs in CI, where only the stand-ins walk (the real hulls walk on the PC). What it does not cover: _tell and the other fx_death paths, the squadron smoke ribbon, shield coverage, and whether the right muzzle fires for the right weapon (it checks placement, not semantics). The Board's condition 1 item is outside its walk, which is how it survived.
4. SHIELD COVERAGE: the bubble still covers the hull. shield_centre() now returns the core, and shield_radii() adds the core's per-axis offset from the box centre to radii that already carried margin: per axis the margin over the far box face works out to 0.05 of the length plus 0.3 (x), 0.175 of the height plus 0.5 (y), 0.15 of the width plus 0.5 (z), with the offset terms cancelling exactly, so every box face, and therefore every hull point's per-axis reach, stays inside on every axis for any core position. The one case per-axis arithmetic does not settle is the ellipsoid's diagonal: a point near a box corner can sit outside an ellipsoid whose every radius clears it, and both legs computed that the corner sum exceeds 1. That gap is inherited, not introduced: the pre-370 bubble had the same radii shape centred on the box centre, box corners are empty on real hulls (the premise of this whole job, and of the check's stand-ins), and the shape itself is issue 371's. NOTE, for 371's file rather than this PR.
