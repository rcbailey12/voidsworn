# Outside check: PR #274 (#121 Nemesis behaviour, Opus worker thread)

Refs #256 (standing outside check, R129 and R132). PR head checked: branch opus/issue-121 at commit cdb36b146055 (merged tip f78f3036 per the PR body).

Legs: blind Rey (full sources, written before the other legs were read), DeepSeek (mechanics axis), Qwen (voice and content axis; the leg derailed, see the screening note in section 4). Chair: Rey.

## Verdict: GO WITH CONDITIONS

The redesign's mechanics verify. The RUN.nem alias is maintained, the run clock has exactly the writers the PR claims, A4 adapts the outgoing commander from his own data, lessons land on the commander met, both save formats migrate, and the line pick draws no PRNG in either language. The conditions are one text class the board named in its own sweep (pronouns the nemSay swap never reaches) and one wording and test gap in design call 4.

## Conditions

1. **Close the pronoun class: three sites where gendered text never passes through nemSay (OBSERVED, blind leg and DeepSeek; chair verified all three).**
   - (a) A twin divergence new in this PR: the JS sector modal renders the adaptation reason swapped, `nemSay(nemAdaptWhy(na, prev.fac), prev)` (campaign_run.js:641), while the Godot modal renders the same reason raw, `C.nemAdaptWhy(na, nf)` (campaign_ui.gd, sector modal). nemAdaptWhy returns table text such as "his own way of war", so a female or Chorus commander reads correctly in JS and as "his" in Godot. This is the one place the PR's "every JS change has its Godot line" claim fails, in a UI-only path the line-identical scenarios cannot pin, because they compare logic records, not rendered strings. Fix here (one line: pass the outgoing commander, or a nemSay-resolved string, through the modal data): the board named twin parity as a headline check for this PR.
   - (b) The map card's strike line is the same class and is not disclosed: "His fleet is coming: your next fight is his." (nemPanel, campaign_run.js:80; Godot twin in campaign_ui.gd _nem_panel). This PR rewired the line's condition from N.strike to RUN.nemStrike and left the text unswapped, two lines away from card text that does go through nemSay. It prints as written for female commanders and for the Chorus (it, its).
   - (c) The clock-full message, "Your next fight will be against his fleet." (campaign_run.js:308; Godot twin in campaign.gd), is the site the PR body does disclose as found, not fixed.
   The ask: fix (a) in this PR; record (b) and (c) as one named follow-up for the text pass (or fix all three here), so the undisclosed site is not lost when the disclosed one is picked up.
2. **Design call 4: correct the wording and pin the carry with a test (OBSERVED, DeepSeek and blind leg; chair verified the guard).** nemClockAdd arms the strike only when the active commander is unmet this sector (`N.met < RUN.sector`, campaign_run.js:308). After a sector's meeting, a refilled clock therefore cannot arm a strike that sector; what crosses the sector advance is a full clock, and the strike arms on the next sector's first clock add, when the incoming commander's met is 0. The behaviour is benign and arguably the intent, but the PR's wording ("a strike pending at a sector's end carries over") describes a state the code never holds, and no test drives the carry through the real advance: check 121-4 sets the sector directly. Correct the wording and add the advance case (arm the clock, advance, assert nemNodeIs on an early node of the new sector).

## Notes

- **The legacy migration head is present (chair settles DeepSeek's open question).** DeepSeek could not verify the legacy-save path because the diff elides the head of nemMigrate. Read in full at head, nemMigrate first adopts a legacy RUN.nem into the empty registry (rebuilding a persona-less commander through the NEM_CARRY fields), and only then sources the run clock from the assignment slot's commander and deletes clock and strike from every commander (campaign_run.js:276-286). The legacy test's expectations are met by that code.
- **newRun builds a commander the first nemActive() replaces (OBSERVED, DeepSeek; pre-existing).** core.js newRun sets RUN.nem = newNemesis(first assignment) with an empty registry, so the first nemActive() constructs a second commander (a full PRNG draw: name, title, persona, traits, portrait, weak) and overwrites it. Not introduced by this PR, but it leaves RUN.nem stale for any direct reader between newRun and the first nemActive(), in a PR whose design call 1 is about not moving PRNG streams. A note for #122.
- **The gloat path bypasses nemSay (OBSERVED code, INFERRED risk, blind leg).** nemOpenLine returns NEM_LINES gloat text raw (campaign_run.js:337). Safe today, since the gloat lines speak only about the player; the convention is unguarded, and any future gloat line with a commander pronoun prints unswapped. Same fragility class as a stale alias that happens to be refreshed.
- **The Crusade fallback has no strike lesson (OBSERVED, blind leg).** When a lost meeting completes the file, a tabled commander records his faction's lessons.strike line; a Crusade commander records nothing, because nemLessonText returns empty for the strike key without a table (campaign_run.js:345-346), so his debrief shows only the file-complete line. Design call 2 covers the weakness fallback and is silent on the strike case. The follow-up Crusade voice job the PR names should close this deliberately.
- **One Chorus motif word in the adopted table (OBSERVED, blind leg; chair verified).** Corsair cunning flee: "Not worth the teeth. The pack comes back richer." (NEM_VOICE, corsair). Teeth belongs to the Chorus set (taste, heat, smell, teeth); the Corsair set is violence, trophies and scrap. The table was pasted as adopted under R101, so this is inherited text; it belongs to the voice style pass, not to this PR's fixes.
- **No test renders modal or panel strings across the twins (OBSERVED, DeepSeek).** The scenarios compare logic records and the clash fixtures compare adaptation cases; nemesis_121_tests.js checks the modal names the right commander but not the parenthetical's pronoun rendering. Condition 1(a) is the bug this gap lets through; a small JS versus Godot modal text assertion for a female or Chorus commander would close the class.
- **One unrelated line rides along (OBSERVED, blind leg).** .gitignore gains checks_report.json (the run_all_checks report file). Harmless, arguably tidy, outside the PR body's file list.

## What verified clean (chair summary of the legs)

- Alias: nemActive() re-resolves RUN.nem from the registry on every call; no surviving reader of N.clock or N.strike outside the migration; the battle snapshot's met stays derived (beaten + scars > 0) while meeting gating uses the per-commander N.met flag.

- A4: the advance captures prev before the sector increment, adapts prev from his own seen with his own faction's adaptFast, then resolves the incoming commander; the cap, computed after the increment, describes the sector just ended; the Chorus SP2 pin (2 - 1) + 1 + 1 = 3 matches the formula. The A4 test fails if the old no-argument call is restored.
- Meetings and lessons: the meeting targets nemAssign[sector - 1] with the return case (SP1 commander met again at SP3); lessons record on the commander met, deduped, with the strike lesson once on a completed file; the tests deep-compare the untouched commander byte for byte.
- Saves: both old formats move the active commander's clock and strike onto the run and strip them from commanders; old commanders gain an empty lessons list; a new save round-trips clock, strike and lessons.
- Voice: the pick is (beaten + scars + sector) mod length in both languages, no PRNG drawn; fall, fall_final (Eclipse last sector, A1) and the silent permanent death are wired as the check table claims; the Crusade fallback returns null or empty at every voice entry point and its lessons fall back to the weakness's own words.
