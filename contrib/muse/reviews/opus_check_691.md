## Conditions

It is disclosed in exactly the right place. But the Nov 12 ruling was a Board-level decision, and an arm declaring it superseded should be ratified by the Board (or Ryan) rather than left as a change-log line. Until ratified, read the A19 entry as provisional. If the Board wants the two-casemate bow back, the route is an exception written into ships.md rule 11, not a weaker check.

2. **Ratify SAME and SPLIT as the standing reading of R241** (blind Rey, Qwen). The brief's done-when lists count, tie, kind and arc (plus turret parenting). The check adds SAME (one slot's mounts match in part type, mount, barrel count and size within x1.3) and SPLIT (every mount fires on every volley under the game's rotating muzzle order), resting on Ryan's refinement, quoted in the check's header: multiple mounts on one slot are fine "if it has to be consistent and line up with the in game behavior". These two rules did the real design work: A16 lost its eight broadside casemates, A17 its flank casemates, A19 its casemates and long tube, E11 its belly shredder, C10 two glands and one pore per gland. ships.md rule 11 as written by this PR already states the multi-mount requirement as binding. The Board should confirm at the rule level, knowing the cost Qwen named: within-slot visual variety (a fixed mount beside a turret, mixed sizes) is now blocked by design, and a future exception means amending the rule, not the ship.

3. **Add a PASS guard to publish.py** (DeepSeek; Qwen noted the same gap as minor). publish.py copies <code>_weapon_match.json into the sheet folder and renders weapon_review.jpg from it without refusing when the record's result is not PASS. build.py writes that JSON before it exits 1 on a failure, so a failed build's output folder can be published by hand and would carry a FAIL record (the review picture would even print FAIL in its title). The normal pipeline cannot reach publish with a failing ship (build.py and contract.to_recipe both refuse), so this is a one-line hardening, not a hole in the gate: refuse in publish.py when the record is not PASS.

4. **Align ships.md rule 11's size wording with what the check enforces** (DeepSeek; the chair agrees). Rule 11 says a weapon's "kind and size fit that weapon". The check enforces kind and mount absolutely (the FITS table) but size only relatively, among the mounts of one slot (SAME, x1.3); a lone mount's absolute size against data.js is not checked, and data.js carries no mount-size field to check it against. Either narrow the rule's wording to the relative requirement or record that the absolute reading is intentionally not enforced. Related small alignment: ARC_TOL is 1.0 degree against core.js inArc's 0.5 slack (the repo's clash.py carries the same 1.0 table, so the check matches existing practice; the Board may align both in a later pass).
