Progression synthesis, Oct 28 program item 1 (renown, LEGACY, admiral unlocks, mastery, core sync, Heat). Chair synthesis of the DeepSeek, Qwen, and Argon (Gemini) blind legs, all pinned to main 264f441d, plus chair verification against the code at that pin. Verdicts and findings are observations for Opus to confirm, not orders.

## Verdict: BYPASSED

Two legs said BYPASSED (DeepSeek, Argon); Qwen said LIVE BUT MISPRICED, which describes the ladder as designed on paper. As shipped, the chair agrees with the majority: the progression economy's main sinks do not exist in play. Boot code (main3d.js:11) grants all 12 LEGACY items (635 renown) and all 24 admirals (930 renown) unless a saved option is explicitly false. That is 1,565 of 1,815 total renown sinks (86.2%) granted before the first battle. The only live sink is bought hull variants (250 renown, about two and a half winning runs). The end-of-run summary itself tells the player the state of the economy: "Spend it on hull variants in Progression" (verified in endRun's carry-forward text).

## Chair verifications (new evidence, all at the pin)

1. The toggle is dead code. A settings handler for the unlock flag exists (campaign3d.js, the c3opt 'unlock' case), but the settings screen renders no button for it, and nothing else in the UI can reach it. No player-facing control can turn the grant off. This corrects a chair screening note on the DeepSeek and Qwen legs, which said nothing writes the option: a writer exists, it is simply unreachable.
2. The purchase path is doubly dead. ACT.buyLegacy and ACT.buyAdmiral are fully implemented (campaign_meta.js:143-144) and have zero UI call sites. The Progression screen has five tabs (variants, mastery, favour, heat, fallen) and no shop. Locked admiral cards still say "Unlock for X renown in Legacy," pointing at a screen that does not exist. DeepSeek's BLOCKER is confirmed.
3. Argon's soft-lock claim needs one correction. With the flag off, other factions' admirals do render locked with no Select button. But admiral selection auto-assigns the faction's first admiral, and neither the Launch action nor newRun checks whether that admiral is owned. So the lock is not a hard soft-lock; it is decorative in both directions: unpurchasable in the UI, unenforced at launch. Flipping the flag without rebuilding the shop produces an incoherent select screen, not a locked game.
4. The end-of-run summary omits core sync entirely (confirmed). It reports renown and mastery only, although favour ticks mid-run when protocols are picked. Tier-ups at 4, 12, and 25 protocols are never announced at the payoff moment, which is why the one progression clock still running at run 5 feels quiet.
5. Mastery XP double-counts elites and bosses (confirmed arithmetic). RUN.stats.battles increments for every battle including elites and bosses, and endRun pays battles + elites*2 + bosses*5 + 10 for a win, so an elite pays 3 total and a boss 6. A standard winning run pays 43 XP. DeepSeek's correction to the chair sheet stands: mastery level 4 (50 XP) takes about 1.2 winning runs per admiral, not 2. Whether the double-count is intended weighting is a design call, but it should be a call, not an accident nobody noticed.
6. Smaller confirmations: the title-screen Progression dot lights at renown >= 15 with no check that anything is buyable (a permanent false positive once variants are exhausted); run-option choices (alternate fleet, second Command) reset when the admiral changes but not when the faction changes, bounded by the mastery gates at run start.

## The intent question

The legs split. Argon read the bypass as a deliberate design change with vestigial code left behind (its evidence: help text written for the open state, a Progression screen purposefully built with five tabs). DeepSeek and Qwen read a leftover debug default. The chair's new evidence tips the balance toward leftover, with high confidence but not certainty: a deliberate removal of the ladder would not normally leave a fully implemented buy handler pair with no buttons, a cost schema maintained on all 36 items, admiral cards directing players to a nonexistent screen, and a settings toggle whose button was never rendered. Every layer of the ladder exists except the two surfaces that would make it reachable. That is the signature of a dev convenience (everything unlocked for testing) that shipped as the default. Only the designer can settle it; the synthesis records the evidence both ways because the fix differs completely by intent (restore the ladder, or delete the dead schema so the help text stops contradicting the code).

## The designer's frame (ruled during this program, Oct 28, 2026)

After the legs were filed, the designer ruled two things that reframe this item. First, the high loss rate (about 80% of runs) is fine and expected in a roguelike; it is not a defect to tune away. Several legs argued from the failure rate itself; those arguments are set aside. What counts against the game is only that progression currently cannot make failure feel like tuition. Second, meta-progression is to be wrapped in a learning fiction: the Sunward Crusade sends a new crusade every generation, and each crusade learns from the past ones. Under that frame the three existing tracks already have their fictions: LEGACY is doctrine (standing orders the Crusade now teaches, funded by what lost crusades recovered), mastery is lineage (an admiral's house passing its annotated charts and playbooks to the next generation), and core sync is memory (the cores remember the fleets that keep flying their protocols). The recommended power shape follows from the frame: horizontal first (alternate fleets, second Commands, variants, starting protocols widen the next crusade's options), vertical modest (chests, command points, price cuts widen its margin), so that completing run 1 stays possible by skill in principle and feels earned in practice, and run 5 reads as a generation of accumulated doctrine rather than a shop emptied. The same learning fiction is to be built per faction in its own idiom: Hegemony doctrine revisions pushed from the Registry's telemetry, Hullbreaker packs raised on the last pack's kills, Chorus broods grown with the last generation's adaptations, long-lived Glasswrights refining their own instruments across projects, and Eclipse iterations compiled from the Archive with the prior iteration's records. The concrete consequence for this item: the post-run summary should present what the next crusade inherits (including core sync, per verification 4), not only currency totals.

## Pacing, if the ladder were live

Chair arithmetic, assumptions stated in the progression pack: a winning run pays about 103 renown; a sector 2 death about 44 (Qwen's own stated assumptions give 47; a sector 1 death 8 to 11). Total sinks 1,815 renown is roughly 18 perfect wins, or a realistic mixed career of 30-plus runs. The largest single item (u_dread at 120) would be a genuine trophy. None of this is reachable today. Two further pacing notes the legs established: Heat pays its +10% per level into this same currency, so as shipped it accelerates nothing that matters, and at an ~18% win rate heavy Heat can make expected renown negative (Qwen) because it converts would-be wins into losses while paying 1 to 4 renown on a loss. Abandoned runs also pay out through endRun, so there is no penalty path distinguishing a quit from a death.

## Run 1 / Run 5 / Run 10

RUN 1: Everything is open. The player has all 24 admirals and all LEGACY power from the first launch, so the run is purely about learning battles. Renown earned is already nearly pointless: variants are the only shelf, and they still cost in-run credits at a shipyard.

RUN 5: The variant shelf (250) is bought out or nearly. Renown accumulates with no sink. The legs split on how rewarded run 5 feels (Argon: strongly; Qwen: modest; DeepSeek: quiet). The chair sides closest to DeepSeek at the payoff moment: core sync is the one clock still running, but per verification 4 the summary never mentions it, so its progress is invisible exactly where a player decides whether to run again. Mastery on a favored admiral lands around here too (level 4 at about 1.2 wins plus loss XP), which is a real reward, and it is per-admiral across 24 tracks.

RUN 10: Qwen's summary stands: grinding a wide matrix rather than climbing a ladder. Heat exists but pays a dead currency; mastery is deep on one or two admirals and zero on the rest; sync approaches full on favored cores (25 protocols each). Nothing at run 10 is scarce, and scarcity is what the first five runs were supposed to build.

## Questions for the designer (collected, per program rules)

1. Is the boot grant a leftover or the design? If it is the design, the dead schema (costs, buy handlers, the orphaned toggle handler, admiral card text) should be deleted so the game stops contradicting its own help text. If it is a leftover, the ladder needs its shop UI rebuilt before the flag can flip, because today there is no screen that sells LEGACY items or admirals.
2. If the ladder is restored, should Launch enforce admiral ownership? Today it does not check, so any restoration that only flips the flag leaves the lock cosmetic.
3. What should Heat pay? Renown (dead as shipped, finite as designed), or mastery, favour, or content access? All three loop legs and both progression legs that addressed it called the current payoff a dead end.
