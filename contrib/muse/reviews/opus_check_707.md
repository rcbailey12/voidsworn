## Conditions

Flash's BLOCKING grade is not adopted because the Done when text specifies the outcome, not the pipeline; the substitution is nonetheless real and should be ratified on the record rather than discovered later.

2. Restore the crest fallback dropped by the _face_base refactor (DeepSeek; chair verified against the diff's removed lines). The old face() returned crest(id) when a picked painting existed but its texture failed to load. The new _face_base() returns _tex(_face_path(id)) directly, and _face_path checks file existence, not load success; face() then returns null when the base is null. A painting that exists but fails to load (corrupt or missing import) now leaves the admiral with no face at all, at any level, where before it fell back to the crest. Low severity, since it needs a broken import to bite, but it is a behaviour regression in shared lookup code: restore the fallback inside _face_base.

3. Pin the two regressions the code itself fears (Qwen, joined by blind Rey and DeepSeek). (a) portraits_check.gd asserts the plain base is identity-equal at level 0 before any levelled call and never re-fetches it afterwards, so a future change that marked the shared base image in place, the exact bleed the face() comment warns about, would pass the suite; re-assert the plain base after the levelled loop. (b) No headless check exercises campaign_ui.gd at all, so the freeze-at-first-level regression the new _face() comment names, and the duplicate faction source (C.ADMIRALS fac in the hook vs crests/index.json in portraits.gd, which would disagree silently), are unpinned; the levelled screenshot demonstrates the hook working today, and a small assertion on its cache-key behaviour keeps it that way. Per-mark-family pins (ring band, corners, bottom edge) belong with (a): today only aggregate pixel counts are asserted, so a dropped mark family would still pass if the total grew.

## Chair verifications and notes

- DeepSeek's blend point is verified on mechanism and adopted as a NOTE: each pass writes col.lerp(dst, 1 - alpha) into a transparent overlay, which stores premultiplied colour (RGB = col x alpha, alpha channel = alpha); blend_rect then applies straight-alpha blending, so the effective alpha is alpha squared. The ring core (0.95) barely notices; the glow terms and the capstone hairline (0.15 x capstone) render much fainter than their constants suggest. The shipped sheet is the tuned output of this exact code and it reads, so this is a latent tuning inconsistency, not a visual defect, and it explains Flash's observation that the capstone hairline can get lost at thumbnail scale: if the Board wants the hairline stronger, fixing the blend math is the principled route rather than raising constants against a squared alpha.
- Visual read (chair, from the shipped sheet): the four rows progress in order across fresh, 1 to 8, cap 3; adjacent levels are subtle, which matches the Done when's "slightly changed"; the corner plate stacks carry the read at small sizes; level 0 is clean. Qwen's taste caveat is shared: on crest portraits the added ring hugs the crest's own gold ring, so levels 7 to 8 and cap 3 read slightly doubled. That is a Ryan-veto item under condition 1, not a defect.
- Cache-key clamps (blind Rey and Qwen): face() keys its cache on level clamped to 0..99 and capstone to 0..9 while the overlay clamps to 8 and 3, so out-of-range calls store duplicate identical textures. Bounded by real callers; tidy-up only.
- The overlay is built square from the image width (blind Rey and Qwen); every shipped portrait is square, so the assumption holds today and is unpinned.
- Capstone without levels (level 0, capstone above 0) draws the hairline alone; the hook cannot produce it (capstone is gated on lineage trees, and capstone mastery opens only after the level 8 evolution per the capstone tests), and no test covers it. Harmless, recorded.
