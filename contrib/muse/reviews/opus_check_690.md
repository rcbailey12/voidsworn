## Chair-verified facts

- Both entry points call all five shared steps in order (init, wait, checkout, preflight, finish); runner_selftest.js asserts that contract statically on any host.
- work_issue.ps1 commit mode writes run_commit.txt (line 390 at head); confirm mode writes confirmed_commit.txt with the remote tip only after its diff check (line 431). PUSHMODE is real, dry or test; finish counts only 'real' toward checked_push, so WORK_TEST_BRANCH pushes cannot release a chain.
- Fix 1 (mirror): bare mirror at Downloads\voidsworn_test\repo-mirror.git created with remote add --mirror=fetch; the origin URL is verified before each fetch and checkout refuses an unexpected origin; fetch --prune runs under an exclusive FileShare.None lock on repo-mirror.git.lock with a 30 minute deadline, held across the local clone; clones are --local with hardlinks and no alternates, and origin is reset to GitHub before work, so no push can write the mirror. A prior checkout is renamed and kept (Keep-Repo), never deleted; the Codex usage-limit path no longer resets or cleans its checkout.
- Fix 4 (chains): checked_push requires exit 0, no partial, push mode real, CHECKS_OK 1 (both runners set it only when node checks and parity both exit 0), run_commit.txt a 40-64 hex id, and confirmed_commit.txt equal to it. wait pins the predecessor's run id for the whole wait, rejects a missing status.json ("text results cannot prove a checked push"), self-waits and changed runs, and caps at 12 hours. init blanks the previous run's resume, commit, confirmation, partial and check files. status.json writes are atomic (GUID temp file plus File.Replace).
- Fix 3 (preflight): per-harness probe words are correct (OpenCode JSON events parsed for text parts; Kimi reply from stdout; Codex reply from its -o file); 90 s cap with a process-tree kill; the reply must equal RUNNER_READY exactly; failure throws a one-line reason that lands in result.txt and status failed, exit 14, before any agent work. Setup failures (missing OpenCode, missing API keys) also route through finish with status failed. The kimicode arm's API key gate is removed because the arm now runs on the Kimi Code CLI and its saved plan login, matching Ryan's subscription-only Kimi ruling; its preflight uses the same CLI.
- Fix 5 (resume): checkout merges refs/remotes/origin/<branch>-partial before either prep writes its task file; both .ps1 prep paths inject resume.txt; a conflict throws with the checkout and MERGE_HEAD preserved. The already-committed-resume path (DeepSeek condition 6) is real in code: both .bat files fall through a quiet cached diff to a findstr "Resumed by merging" gate, and work_issue.ps1 commit mode exits 7 only when there is no resume note or no diff between base_commit.txt and HEAD. It is not exercised end to end by the selftest, whose test mode stops before publish; it is code-verified, and its first live exercise is condition 4's witness item.
- Flash's conditions, answered: (1) the mirror lock it asked to verify exists exactly as described above, and the selftest's concurrency case proves two simultaneous checkouts serialize and both succeed; (2) the selftest does cover a preflight timeout (probe tree killed, job stops with exit 14) and a provider-error-with-exit-0 case for every arm; a literal HTTP 429 response is not stubbed, though 'rate.limit' is in the preflight error-pattern list and a 429 body would also have to produce the exact RUNNER_READY reply to pass, which it cannot.
