# Red team audit: Producer leg (Rey, blind)

Seat: Producer, scope realist. Target: the program around Voidsworn, not the game's fiction or feel. Evidence: the producer pack (core pack, claims register, program scale facts, OPUS_HANDOFF, the Godot desktop 3D brief, the desktop performance audit, the saves and persistence audit, the telemetry spec) plus my own counts of the local clone at ~/workspace/voidsworn-fresh, marked OBSERVED where used.

## Findings

**1. The evidence program outproduces the build, and the ratio is measurable.** OBSERVED, my count of the local clone: of 1,031 commits since Oct 20, 2026, 515 touch contrib/ only and 322 touch godot/ or root JS. Review and synthesis commits outnumber code commits by about 1.6 to 1. OBSERVED: contrib/ holds 816 files (64 MB on disk) against a browser game of 8,947 lines of JS; contrib/muse/reviews/ alone holds 124 files in a clone that lags main. The game is being described faster than it is being changed. Cost: every synthesis cites line numbers and a pin that the next program already knows will rot (the drift verdict was ROT, 3 of 4), so a growing share of each new pass is spent re-verifying what the last pass established instead of advancing the build.

**2. The project wrote 48 regression tests, watched 40 of them fail, and moved on to drafting content.** OBSERVED (pack): findings-to-tests at the pin stands at 8 PASS / 40 FAIL, and the failures are "failures are correct regression tests against unfixed defects" (9 words). This is the single cheapest verified fix list the project owns: each failing test is a defect already found, already reproduced, already written down in executable form. Cost: while those 40 sit unfixed, the Godot port re-implements the same systems from the browser build as its oracle, and any defect the oracle carries can be ported as correct behavior. The tests also decay as the pin moves, so the list gets more expensive to spend the longer it waits.

**3. Sequencing is inverted at the cutover: the instrumentation spec exists before the thing it instruments.** OBSERVED (telemetry spec): "three designer rulings end with "revisit with actual play data,"" and the spec exists because "play data does not exist unless the build logs it on purpose." OBSERVED (pack): there is no playable Godot run yet; the migration order puts one playable battle second and the full run third. So three settled rulings (regroup tension, Nemesis snowball, generational payoff) are parked behind an event that has not happened: a human playing the Godot build. INFERRED: the project's critical path is not blocked by missing analysis, it is blocked by a milestone the analysis program cannot produce. Every additional audit wave that ends in another revisit-with-data ruling lengthens a queue whose only drain is play.

**4. Effects code mass is running ahead of the run layer it will have to serve.** OBSERVED, my count: godot/fx holds 18 GDScript files totaling 9,418 lines; godot/rules holds 5,821 lines and godot/campaign 2,930. Effects code already outweighs rules and campaign combined, in a migration whose own stated order is rules parity, one playable battle, the whole run, and only then the big effects pass. OBSERVED (Godot brief): "The real budget gets set by the effects-pass performance budget item" using PERFCAP on Ryan's PC, meaning the performance budget for all that fx code is not yet set. INFERRED: effects built before the budget exists and before phased activation (ruled, unimplemented in the browser build) reshapes the battle layer are the program's largest single rework exposure.

**5. Content is stockpiling faster than it can be integrated, and some of it polishes structures already ruled defective.** OBSERVED (pack): the filed inventory is 216 tree texts, 33 event variants, 41 Nemesis lines, 16 tutorial tips, 30 firstrun framing units, and one Eclipse battleship entry whose ship id is still undecided (d_meridian vs d_wraith, left to Opus). None of it ships until someone integrates it into data.js, and data.js is code (697 lines holding every table). OBSERVED (pack): 7 of the 33 events that just received variant text fail the free-exit guarantee eval (26 of 33 pass), so finished prose now sits on option structures a prior ruling already found defective. Cost: each unintegrated batch is a future merge task with stale risk, and integration capacity belongs to the same single implementer lane as findings 1 and 2.

**6. The save system's load-bearing constraint was discovered by an audit, not stated by the build.** OBSERVED (saves audit): "Id stability is load-bearing for this save format" and a renamed hull id silently deletes that ship, its captain, its perks, and its fitted refits at load, with the only record in a raw repaired JSON "which no UI reads back." OBSERVED (pack): the cutover itself was a BLOCKER found by the saves audit (browser progression is lost without an importer), and the importer fixtures were then built by the audit side of the program. INFERRED: the two most consequential production facts of the last week, importer necessity and id stability, arrived as audit findings rather than as engineering constraints stated up front. That is the review apparatus doing the build's planning for it, at audit speed.

**7. The evidence machine runs on static reads because the dynamic fuel is the scarcest resource in the project.** OBSERVED (performance audit): "No runtime profiling was done; this is a static read." OBSERVED (saves audit): "Code reads only; nothing was run." OBSERVED (pack): the repair tension question consumed a 60,000-regroup simulation and ended ruled "accept as is," pending play data. INFERRED: sims and static reads are substitutes the program burns because the real instrument, Ryan playing the game, is also the sign-off gate for the playable battle and the only source of the play data three rulings wait on. One person's hands are the bottleneck for testing, sign-off, and ruling closure simultaneously, and no program document in the pack names that as a schedule risk.

**8. Coordination artifacts decay at the same rate as findings.** OBSERVED (OPUS_HANDOFF): the handoff is dated Oct 24, 2026 and required a names addendum on Oct 29 because "its ruling sections use the naming layer of that day." It also has to state its own limit: "Rey is not a verification gate over your work." OBSERVED (pack): this audit's evidence was "built Oct 30, 2026 from main head b3a3b802" against code described at "pin 264f441d," while my clone sits at a third head (cbffcaf). Three reference points in one evidence base. INFERRED: at the current production rate, any document that routes work (handoffs, registries, reading plans) has a useful life measured in days, and the program pays a continuing tax to keep its own map readable.

**9. Scope grows by ruling while the existing scope carries duplication verdicts.** OBSERVED (claims register): weapons, squadrons, and boons all carry DUPLICATES WITH PAINT verdicts, and faction shape is SHAPES PARTIAL (4 of 4). OBSERVED (pack): in the same period the roster gained a new hull class entry (the Eclipse battleship) and the content matrix grew to 216 tree texts across six factions and 24 admirals. INFERRED: each added hull and text multiplies the balance and QA surface (the wave 3 faction matrix already ran at n=6 per cell, smoke rather than signal) while the sameness problem in the existing surface stays open. A producer reads this as adding rooms to a house whose existing rooms were just reported as copies of each other.

**10. This audit is the fourth comprehensive pass in eight days, and its marginal finding rate is visibly falling.** OBSERVED (pack evidence base): the Oct 27 program, the Oct 28 programs, ten Oct 29 syntheses, the savings-pass waves, and now a nine-persona red team, all inside Oct 23 to Oct 30 by the commit dates in my clone's log. The Oct 29 verdicts largely restate the Oct 27 and 28 problem shapes (duplicates, friction, rot) at higher confidence. INFERRED: the program has crossed the point where another full pass finds new classes of problems; what it finds now is confirmation. Confirmation has value once. Run as a standing weekly rhythm against a single-implementer build, it converts directly into the backlog growth measured in findings 1, 2, and 5. The cut a producer makes here is not a persona or a document; it is the next audit wave, deferred until the Godot run is playable and the 40 failing tests are the agenda instead of the backdrop.

## Verdict

Verdict: FREEZE THE AUDITS AND SHIP THE RUN. The program's own numbers convict it: 515 review commits against 322 code commits since Oct 20, and 40 written regression tests failing against unfixed defects while a fourth comprehensive audit launches. The single most important attack: the critical path to everything the rulings are waiting on (play data, sign-off, cutover) is one playable Godot run, and the review apparatus is now the largest competitor for the hours that would produce it.
