## Code question answers

### Q1. Can a Chorus admiral roll as the Nemesis in stream B code? YES, settled.

campaign.gd line 945 builds the run's foe list as a shuffle of every faction except the player's own ("foes = shuffle(RUN_FACTIONS.filter(func(f): return f != fac))"), and newNemesis (campaign.gd line 1517) takes the Nemesis faction from foes[3], with a fallback pick from the same non-player pool. RUN_FACTIONS is the six-faction table (story.gd reads the same table; its fallback list at story.gd line 51 is all six, chorus included). So whenever the player's faction is not Chorus, Chorus is in the pool and can land at index 3. Consequence: fix 7 was required, not optional, and the revised Table A and the pronoun code both handle the case (tokens.gd gives a Chorus Nemesis "it"). One boundary: the draw itself is in the Godot campaign port of the B4 layer; the R42 stream B generation enriches the same RUN.nem fields (rival.gd's header lists which fields come from B4 today and which stream B adds), and nothing in either layer excludes Chorus.

### Q2. Does anything follow Beat 3 in a run? Partly settled; the sharp form is now moot.

What the code settles: Beat 3 is the arc's end, not the run's end. story.gd arc_end and career.gd record_arc_end fire when the beat 3 fight is decided (medal, title, paint, Chronicle row, unlock id reported), while the run's own end is a separate campaign page (story.gd watches for page kind "end" independently). The beat sits in sector III, and sector III continues under normal campaign flow (the campaign has shop actions, campaign.gd lines 1381-1414, and nodes beyond the story event). What the code does not settle: the arc beats are not yet wired into campaign.gd (no arc_beat calls there; story.gd's header says "arc beats (plumbing; arc files arrive after approval)", and godot/story/data/arcs/ does not exist yet), so the exact node order around the beat 3 event cannot be verified from the build today. The specific worry behind the question is moot in the revised text: the Corsair Beat 3 no longer pays a credit reward at all (its options are experience with an obligation, a 60-credit spend for repairs, and the Mott blue), so no reward lands after the last shop by construction.

### Q3. Beat 2 flag naming in the build, and variation beyond the outlines. Mechanism landed; arc data not yet built.

arc.gd's option shape carries an optional named flag per option ("flag a story flag it sets, written as an fl counter, so the existing eventFlags stores it in RUN.flags"), and its condition language can test any flag ("flag:<name>    the run has that flag (RUN.flags, written by earlier choices)"). So the build fully supports named Beat 2 flags and Beat 3 callbacks on paper-checkable names, matching fix 10's intent. But the per-faction arc files the engine loads (res://story/data/arcs/<faction>.json) do not exist on main yet; godot/story/data holds arcs.json (the rewards table: medal, title, paint, unlock_variant per faction), rival_lines.json, voices.json, medals.json and titles.json only. story.gd is explicit that this is sequencing, not omission: "arc files arrive after approval", which is the B5 gate doing its job. On the synthesis's broader third question (does the game add variation beyond the outlines): yes, in design and in plumbing. outlines_variants.md holds a full B version of every beat for all six factions ("Both versions set the same flags with the same effects"), skim cards, and twelve shared rival incidents; arc.gd pick_variant rotates toward the version the profile has seen less; rival.gd picks lines from pools by a stable hash of the Nemesis's name, the moment and a seed.

### Rival line pools beyond the NEM_LINES placeholders? YES, they exist now.

This closes the open item the Nemesis review (Job 2) carried. godot/story/data/rival_lines.json is on main at 25,762 bytes, and godot/story/rival.gd reads it. Per faction it holds: deed pools by personality (the Table A source), final_by pools (sun, remembers, mercy, ruthless; the Table B source), memory lines keyed by how you beat him (lance, torp, sq, ram, board, battery, evasive, derived from last_beat or inferred from adapt and seen via ADAPT_TO_MEMORY and SEEN_TO_MEMORY), scar lines, and moment lines for hail, again, beaten, death, gloat, kill, signature and final, with per-personality overrides for hail and beaten. rival.gd opening() picks among again, memory and scar lines on rematches, so the single-template "again" line the four Job 2 legs criticised is replaced by a pool with memory-keyed lines at its centre. Caveat for Opus: the pools are presentation-only and pick by name hash, never the rules PRNG (rival.gd header), and the personality ids the outlines assume (proud, cruel, cunning, zealous, cold, mocking) are the R42 proposal; rival.gd's header notes personality is a stream B field, so pool coverage depends on stream B emitting those ids.

### {rival} pronoun handling for female commanders? YES, implemented in tokens.gd.

tokens.gd pronouns(nem) returns a full {he, him, his} set with capitalised forms: from nem.g or nem.gender when present; a Chorus faction Nemesis defaults to neuter ("it"); otherwise it infers from a FEMININE first-name list (33 names, including Petra and Ilyra) matched against the captain name pools, defaulting to male. fill() applies the set to the whole card, including inside the deed and rival line text, which are pronoun-filled first. The dependency is named in the file: the name list is a fallback, and "Stream B is asked to add nem.g = "m" | "f" | "n"". Until stream B emits that field, correctness rests on the name list covering the generated name pools.

## Job 6 trigger ruling: NOT LANDED. Job 6 stays blocked.

The brief's trigger has two halves: stream B has ADDED the six story hull variants (implementation), AND sim numbers exist for them. Neither half is met.

- Implementation: data.js on main contains HULL_VARIANTS, but none of the six unlock ids appears in it (grep counts: vs_penitent_l 0, h_interdictor_e 0, c_marauder_g 0, b_razor_e 0, i_carrier_a 0, d_jackal_h 0). godot/story/unlocks.md itself still reads "Status: DRAFT" and lists the work as instructions to stream B in the future tense ("Add the six rows to HULL_VARIANTS with cost: 0 and arc: '<faction>'"). What does exist is the story-side record: arcs.json carries each faction's unlock_variant id and name, and career.gd stores the unlock id in arc_rewards when an arc is won (story layer reporting only, exactly as unlocks.md assigns it).
- Sim numbers: contrib/opus/compute/streamb/pass1_report.md is the stream B pass 1 report (B3 step 1, faction rules and travelling torpedoes, against the B-19 baseline). It contains no variant ids, no HULL_VARIANTS mention and no unlock content (grep count 0 for all seven terms). Its matrices are faction, boss, archetype and campaign passes over the standard hulls. There are no sim numbers for the six variants anywhere in the report.

What would unblock Job 6: the six rows landing in data.js HULL_VARIANTS (and through the exporter into the Godot tables), plus a sim pass that fields them (unlocks.md suggests bossmatrix and fmatrix with the variant in the starting fleet). Until then there is nothing to balance-check against the base hulls.

## Surprises and notes for the chair

1. The revision was driven by the two Claude reviewers (per the outlines header), yet it lands 7 of the synthesis's 10 fixes clean and the rest partially. The four-leg synthesis and the Claude pair converged on the same defect list; the incorporation did not wait for the synthesis.
2. Fix 3 landed by deletion, not renaming: there are no sample rivals left to rename. The Setekh problem, the Petra Lindqvist and Ilyra Glasswing pronoun problem, and the humanoid-deed problem were all cut at the same root by making {rival} always the generated Nemesis.
3. The one clean miss in an otherwise thorough naming pass is a single option: Chorus Beat 2 "Dive and eat" (outlines.md line 182) has no flag. It is also the only standard option whose effect (clock moves on) mirrors a flagged sibling pattern, so the omission reads as a slip, not a design choice.
4. The B-variant file is a bigger replay answer than any leg asked for: full second versions of all 18 beats with identical flags and effects, plus skim cards. The synthesis's staleness concern (agreement point 6) is answered structurally, pending the arc JSON build.
5. Two of the Job 2 Nemesis review's open items close here as a side effect: rival line pools exist (rival_lines.json, 25,762 bytes, with memory-keyed lines), and Chorus can be the Nemesis (campaign.gd foes[3] draw), which retroactively makes the Job 2 faction-safety discussion load-bearing.
6. The Deathless crest still opens with "a crowned eye" (line 255). The tomb door is gone from it, but if Ryan wants the crown density down as the fix literally said, the crest is the one place it survives in the Deathless arc proper (the other crown hits are the change note and the Corsair treasure text).
