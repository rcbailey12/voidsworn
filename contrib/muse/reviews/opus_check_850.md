# Check: PR 850, commit 4a7b21fa7688, "on Linux take the first git that Get-Command finds"

Refs #256. Batch item 3 (Board brief, issue 256 comment 6915278472). The commit changes one line, tools/pc/runner_common.ps1 line 48, in the runner's Git function: on Unix, the git executable was taken as (Get-Command git -CommandType Application).Source and is now @(Get-Command git -CommandType Application)[0].Source. Chair-verified by reproduction on a Linux host with two gits installed, not by reading alone.

## Verdict: GO WITH CONDITIONS (the condition is on the PR, not on this commit)

The commit is correct, and it fixes exactly the break its message names. On a host with two git applications (this check host has /usr/bin/git and /bin/git, as the CI runner does), Get-Command returns two entries: the old expression's .Source member-enumerates to an Object[] of both paths, and the runner dies with "The term '/usr/bin/git /bin/git' is not recognized" (reproduced by reverting the line in a scratch tree and rerunning runner_job_tests: it fails at the first git-using scenario). The new expression yields the single string "/usr/bin/git", the first git Get-Command finds, as the commit says. With the fix in place, every git-using scenario in runner_job_tests passes on the two-git host: the Base fetch and merge scenarios, the checked push, the conflict case. The Windows path is untouched ('git.exe' literal), and the PC_TEST_GIT stub override still applies after the line.

The condition: PR 850's Standing checks are still red at this head, for a second reason this commit does not cover. The chair ran the full standing suite locally on the branch tree (Node 22, pwsh 7.4): every row passes except runner_job_tests, and with the git fix working, that test now gets past the runner scenarios and dies later, in codex_issue.ps1 prep mode at line 25, where the prompt build reads $env:USERPROFILE (Join-Path for the Godot path). USERPROFILE is a Windows variable and is unset on the Linux CI host, so Join-Path binds null and prep exits before the agent starts. runner_job_tests.js is new in this branch (added by e7de0464, the 846 runner commit), which is why no earlier PR's CI met it: this is the first branch to drive codex_issue.ps1 prep on a Linux host. Before PR 850 merges, either codex_issue.ps1 should default its Godot path when USERPROFILE is absent, or the test should set USERPROFILE in the environment it spawns. On the Board's Windows PC both are moot, which is presumably why the branch looked green there.

Method note: the local reproduction used the branch tree as pushed (CI additionally merges current main in before testing; the failing file and test are the branch's own, so the delta does not bear on the finding). The job's step list in CI (step 6, Run all standing checks, failure; the em-dash step green) matches the local result.
