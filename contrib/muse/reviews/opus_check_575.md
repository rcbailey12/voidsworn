### Condition

For the workhorse that holds: every run has its own out folder. For Codex it does not: board\issue-<n> is shared between reruns, and the guard copies with Copy-Item -Force, so a rerun that refuses a file at the same path silently overwrites the earlier run's copy in out\refused. The refused file itself stays in the working tree, and the worker report discloses the overwrite in its own "not sure of" list, so nothing here is hidden; but the claim as worded is false for one of the two runners. Two ways to satisfy the check: give Codex's refused copies a per-run subfolder (the workhorse's shape), or narrow the claim where the runner is documented and record the Codex overwrite as accepted behaviour. DeepSeek graded this blocking outright; Qwen graded it a note because the underlying file is never deleted. The chair sides with DeepSeek on the grade, because question 2's wording is the contract this PR is being merged under, and with the Board choosing the remedy, since the fix and the acceptance are both cheap.

Everything else in the Board's six questions verifies clean, in the code and, where the dry runs reach, in their output. The chair read work_issue.ps1, work_issue.bat and codex_issue.bat whole, the patch against the current auto_pr.yml, and the run evidence files directly.

## The Board's six questions

1. PARTIAL: verified. In work_issue.bat, any non-zero agent exit sets PARTIAL (124 is then named as the time cap), and a surviving MERGE_HEAD sets it too; the push target becomes <branch>-partial and the runner checks are skipped. codex_issue.bat has the identical shape on its CX variable. The patch stops the pull request two ways: negative trigger patterns for codex/issue-*-partial and work/issue-*-partial (exactly the two runner families that produce partial branches), and an in-step case guard that exits 0 for any branch ending in -partial before gh is called, which covers any other prefix as a backstop. The patch's context matches auto_pr.yml at head, and the worker's git apply --check result is consistent with what the chair read. Run 2's output shows the whole path working (exit 124, partial branch, pushed diff checked). Until the Board applies the patch, a partial push to a real work/ branch would still open a pull request; the report's swap order (patch first, then the PC copy, and only when no run is active) is the right order and the check endorses it.
2. REFUSE LIST: verified, one condition above. Refuse-Reason (work_issue.ps1) covers every named category: over the size limit (default 8 MB, WORK_MAX_FILE_MB overrides) for added or modified files, anything under godot/gen and (beyond the brief) godot/.godot at any status, ship files under godot/assets/ships/<hull>/ except previews and test at any status, new .uid files (status A), and .import files both re-saved (M) and new (A). The guard copies each refused file (except deletions) into out\refused before unstaging it, fails the run (exit 1, which the .bat files turn into their guard-failure exit) if any copy fails or any refused path is still staged afterwards, and never deletes anything: tidy never touches out\. Run 1's refused list and result match the categories one for one. A modified .uid (status M) passes the guard; both legs read that as deliberate (only Godot-generated new .uid files are the target), and the chair agrees, noted here so the Board can say if it wants otherwise.
3. NO FORCE PUSH: verified. The commit step (work_issue.ps1 commit) reads the branch's earlier tip by ls-remote, fetches it, and builds the run's commit with write-tree and commit-tree whose parents are the agent's HEAD, MERGE_HEAD if one survives, and the earlier tip; then it moves HEAD with update-ref, each step's exit code checked (exit 11 on failure, 12 when the earlier tip cannot be read). Both .bat files push with a plain git push origin HEAD:refs/heads/<branch>; there is no force flag or + refspec anywhere in either runner. If the branch moved between the fetch and the push, the push is refused as non-fast-forward and both runners keep the work as a binary change.patch and exit 8. Run 3's commit carries the two parents the report claims (the agent's merge and run 1's tip), and the report's post-run 6 compare reads (both earlier tips still reachable, behind_by 0) are the right shape of proof.
4. THE ISSUE 541 FAILURE: verified, and this is the strongest part of the PR. The root cause is established from the old run's own files (commit.txt at 0 bytes, written two minutes after the disk filled; the old runner never checked its commit's exit code). Runner 2 answers it at three depths: the message can no longer be empty (an empty commit.txt is replaced by a plain runner message with a warning, and the runner's own block is appended in every case); the commit is plumbing with every exit code checked, so a disk-full failure stops at exit 11 with the change saved as a patch; and before any push, the commit must carry exactly the staged numstat with nothing left staged, else DIFF MISMATCH, exit 10, nothing pushed. That comparison runs before the push in the code (the .bat pushes only after commit returns 0), which is what the Board asked. Run 4 reproduces the 541 shape with the skipcommit fault and the mismatch file in the PR shows it firing (staged 3 files, 0 in the commit, branch unchanged). After the push, confirm re-reads GitHub's branch and compares the diff again; its failure path is unproved (see notes), its pass path ran in five of the six runs.
