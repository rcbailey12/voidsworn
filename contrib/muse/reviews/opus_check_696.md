Flash's leg would ratify leaving the sheet stale under the cap; the rest of the council and the chair require the fix or the explicit record.
2. **render_R244.py breaks when PR 691 lands.** It forces CPU by string-searching build.py for the literal line `sc.cycles.device = 'GPU'`; PR 691 replaced that line with the SHEET_DEVICE environment form, so the search raises and the R244 render path dies. Fix the script to prefer the SHEET_DEVICE environment variable (falling back to the string patch only where the literal still exists), or retire it on the record as a one-run job artefact. Either way, record the merge order for PRs 691 and 696, and re-run the affected script after the second one lands. assemble_R244.py has no such dependency.
3. **Rule 11 collision.** This PR adds R244 to ships.md as binding rule 11; PR 691 adds R241 as rule 11 from the same base. Whichever merges second renumbers its rule, with in-repo cross-references to rule 11 checked in the same commit.
4. **Ratify the build mechanism.** The well cut applies a boolean modifier inside build() via bpy.ops.object.modifier_apply against the view layer's active object. It worked in the arm's CPU runs (every record above passes at this head) and the cutters are removed after applying, but it is a fragile pattern for the next arm that rebuilds A20. The Board should ratify it as standing practice or move it into a kit helper. The two R244 job scripts also live in the sheet folder; ratify that placement or record them as Board-side artefacts.
5. **Board picture ratification.** No leg inspected the picture pixels; the angular-flank claim rests on the section-table change plus the before/after pictures. The Board should eyeball A20_side_R244_before_after.jpg and the flank detail view and ratify the look, since the outline number moved the wrong way by a hair (condition preamble, section above).
