## The five conditions

1. **Break lines: MET.** tools/recipe/audit.py refuses to run when the blend carries no break lines of its own ('r209_t_lines' or 'r209_l_line' missing appends a failure and audit.json is FAIL, exit 1), and otherwise passes them explicitly to PB.audit. The gated path has no fallback. (Qwen, DeepSeek, Rey concur; Grok's contrary mechanism is rejected below.)
2. **Into-the-ship test in the audited artifact: MET.** armA7.py appends the plumbing gun triples (name, aim, mount normal) to its GUNS and the scene record; audit.py rebuilds the triples from r209_guns; plumbing.audit (line 177) runs aim_ok against each normal and appends an "aims into the ship" problem; audit.json carries guns_with_normals and guns_into_ship; 4_parts_kit.bat gates on the audit's exit code; audit_selftest.py runs in stage 4 and refuses three broken copies.
3. **Install guard before stage 1: MET.** env.bat, called first by every stage bat, installs scipy and Pillow into Blender's python before stage work; 1_concept_in.bat checks the concept write's error level and the PNG's existence and exits 1 otherwise. Softness, accepted by all legs: if the install itself fails env.bat only warns, and the failure surfaces at stage 1's write, which stops.
4. **Stages stop on their own failures: MET.** All seven stage bats were read. Stage 2 fails when no shape reference exists afterwards; stages 3 and 5 refuse to start without it; stage 4 checks the audit ran, gates on its exit code and on the self-test, and fails when the outline gate fails; stage 6 checks its blend and both log markers; stage 7 gates on check_export and its self-test before installing. One nit (DeepSeek, Rey): stage 4 proves the build happened by a log marker rather than the blend's existence; a missing blend still fails the audit step's own checks, so the stage stops either way.
5. **Stage 5 ship-selected: MET.** env.bat reads the ship json's bake key into BAKE (default bakeAb6.py, which builds whichever hull module the json names); 5_paint_bake.bat runs %BAKE%; C15s_23.json carries the key; RECIPE.md's stage table describes the mechanism.

## Conditions

1. **audit.py must fail when any gun lacks its mount normal, not only when all do.** Today the guard is `elif not any(g[2] is not None for g in guns)`: a build with one normal and twenty-three without passes the guard, the twenty-three are never into-ship tested, and stage 4 does not fail, though audit.json's guns_with_normals count shows the shortfall to a reader. This is the #286 shape (a guard reporting presence, not pinning the claim). One comparison closes it: fail when guns_with_normals is less than the gun count. (All three seated legs and the blind leg found this independently.)
2. **check_export.py must enforce the breach contract its own RECIPE states.** RECIPE.md's hard point table specifies six hp_breach anchors, two per section (prow, mid, eng), each at least 0.03 from every part, +Y the outward normal. The check requires only that at least one breach point exists; it records each point's up vector in its report and never tests it, never counts to six, and the 0.03 clearance is a distance to parts, which the mesh-distance test does not measure. The damage build (RECIPE.md stage 7 list, item 2) builds on these anchors next; pin the contract now while the check is young. (DeepSeek, raised as HIGH; Qwen noted the count; chair verified against RECIPE.md.)

## NOTEs

- **Weapon extras are presence-checked only, and one required key is missing from the list.** check_export.py tests that kind, size, arc, arc_deg, slot, weapon and radius exist in a weapon point's extras; RECIPE.md's table lists eight extras, including socket, which the check never requires; and no extras value is compared with the node name or data.js, so a point can carry a slot or weapon in its extras that disagrees with its name and pass. (DeepSeek, Qwen.)
- **The tolerance is not what the headers say.** check_export.py's header and RECIPE.md both promise failure beyond "0.012 of the ship's length" from the mesh; the code compares the absolute glb-unit distance against 0.012 and never uses the ship's box, which it computes for its notes, to scale it. On a unit-length export the readings agree; on the next ship, at a different scale, the check silently tightens or loosens, and the self-test's 0.05 displacement is calibrated to the absolute reading. (Blind Rey, DeepSeek.)
- **Break-line presence is not break-line content.** An empty r209_t_lines passes audit.py's guard and tests no transverse lines. A non-empty assertion is one line next to condition 1's fix. (DeepSeek.)
- **The self-tests prove their headline failures only.** check_export_selftest covers slot removal, off-mesh and backward aim of the check's ten-plus failure modes; side rules, engine facing, missing required points, non-child points, missing maps and the unbaked refusal are code-covered only. audit_selftest's into_ship case negates the first gun's normal exactly (dot at -1), the easiest detection, and does not assert its precondition: if the first gun had no normal the mutation would be skipped and the audit would pass the unmodified build, which the self-test scores as BAD, so the failure is loud but its printed reason ("the audit PASSED a broken build") would be wrong. Qwen proposed this as a condition; the chair records it as a NOTE because the failure direction is safe. Adding one side-rule case and one missing-point case to the export self-test, as Qwen suggests, is cheap and worth doing with condition 2.
- **The bake path's own audit call still runs on defaults.** bakeAb6.py (line 151) calls PB.audit with A3.GUNS and no break lines, so plumbing falls back to common.py's module values for its build note. The gated artifact (stage 4's audit of the built blend) is unaffected; the note is a reader trap of the same family condition 1 closed on the main path. (Blind Rey, Qwen, Grok.)
- **check_export never compares a hard point with the muzzle it came from.** RECIPE.md says a weapon hard point "is always on a real barrel" because the writer places points from plumbing.register_gun's registry; the check proves only near-mesh. A checker-side comparison against the r209_hp record would make the claim tested rather than constructed. (DeepSeek.)
- **The floating test's word is "touches"; its test is intersection.** plumbing's touching set comes from BVHTree overlap, which needs intersecting faces; a part resting exactly on another part without interpenetration is not excused by it and falls to the hull-distance sample. The code comment and RECIPE.md both say "touches". The scope limit itself (chains excused) is documented and accepted; the verb is stronger than the test. (DeepSeek.)
- **Ab7's outline gate reads 89.7, under the 90 gate**, per the PR body and RECIPE.md; stage 4 now exits on that honestly. That is the ship's state for the Board's merge judgement (round 8 is already working the bow), not a defect in this PR's recipe changes. (Qwen.)
