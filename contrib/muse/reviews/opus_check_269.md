## Notes

- **N1. The standing tests are narrower than the claims around them (OBSERVED, blind leg and DeepSeek, converging).** ui_spec_tests.js:51 is a literal `check(true, 'text floor scan ran')`, an unconditional pass inside the "40 of 40". The text-floor scan behind it sees only listed call shapes: it misses theme default font sizes (the `default_font_size = s(15)` form) and raw `add_theme_font_size_override("font_size", 11)` literals, and never asserts that any rows were scanned, so a regex that stops matching passes silently. The one-law check is a heuristic (a literal `/1080` plus the substring `clamp` in one file); a private copy using a named constant or minf/maxf passes. Stale PAIRS entries in ui_constants_diff.js print a NOTE and exit 0. ui_scale.gd's comment ("Checked by script ... on every font size literal in godot/ui and godot/main") and ui_spec.md 4.3 ("scans every font size literal") overstate all of this. Narrow the wording or harden the checks.
- **N2. Moment 7 can pass without proving what its notes say (OBSERVED, DeepSeek and blind leg).** ui_shots.gd wraps the toggle-refocus checks in `if row != null:` with no failing else, so if the "Firing arcs" row is ever absent the refocus assertion is silently skipped and the run still passes. Separately, the ring assertion checks the focus stylebox is a StyleBoxFlat with draw_center off, never its border width or colour, so a 1 px dim ring would pass a note that reads "a visible focus ring".
- **N3. The loading line samples its scale once (INFERRED, DeepSeek).** load_screen.gd sets the label size from the viewport in _ready and never follows a resize, where the other screens rescale. The impact sweep says the line now scales but not that it is frozen at first layout. Short-lived screen, low severity; the board should decide it knowingly.
- **N4. The end card's focus grab is one-shot (INFERRED, blind leg; design intent per DeepSeek).** hud.gd:1241-1243 grabs focus after 0.75 s only if nothing holds focus at that instant, and never retries. The guard is deliberate (the grab must not steal focus from a menu opened meanwhile), but if a transient holder releases after the timer, Continue stays unfocused, against debrief_spec.md section 3 item 8. A deferred second attempt closes it.
- **N5. A rebuild while the menu is open loses the menu's focus row (OBSERVED, blind leg).** hud.gd _rebuild sets menu to null (line 148) before replaying show_menu from its saved call, so the refocus index computes from no menu and lands on the first row. ui_spec.md section 6 promises the row is kept for a toggle; the rebuild path is the same replay mechanism and drops it. Moment 7 does not exercise this path.
- **N6. The focus ring's expand margins do not scale (OBSERVED, DeepSeek).** _theme() scales the ring's border width and corner radius through s() but sets all four expand margins to a raw 3. At k = 2 the ring is 4 px wide and still sits 3 px out. Cosmetic.
- **N7. "Stops at 2.2" holds only at player scale 1.0 (OBSERVED, blind leg).** ui_scale.gd:32 multiplies after the clamp, so at player scale 1.4 the effective k reaches 3.08 at tall windows. ui_spec.md 4.4 documents the after-clamp multiplication, so this is the design; one clarifying line in 4.1 when follow-up job A ships the settings entry keeps it from being re-litigated there.
- **N8. The colour extraction behind the constants table has blind spots (OBSERVED, DeepSeek).** ui_constants_diff.js's hex regex cannot match 8-digit hex (#RRGGBBAA), its CSS variable regex sees only hex-valued variables (not rgb() or var() values), and its HTML id skip is ineffective at line start, where a 3-hex fragment identifier counts as a colour. The on-palette table can under-report off-palette colours.
- **N9. R1 to R3 naming collision in ui_spec.md section 2 (OBSERVED, Qwen).** Section 2 lists the Nov 6 audit's owner rulings R1, R2, R3 alongside FINDINGS rows under one "Rulings applied" heading. In FINDINGS, R2 is the dead-star board and R3 is shield colours. The opening paragraph distinguishes the two systems; section 2 does not repeat the distinction. One line there closes the misreading risk.
- **N10. Two wording slips in the PR body (OBSERVED, Qwen and blind leg).** The defaults summary says the three new entries are "off or Normal"; ui_spec.md 7.5 has Map detail at Auto. And "a recorded choice per divergence" overstates HD7 and HD11 slightly: both are marked Open with a stated interim holder (the port value) and a stated resolution round (U-A), which is a recorded hold, not a final choice.
- **N11. FRIEND is one hex step off in code, already tracked (OBSERVED, Qwen).** The spec palette adopts #8ff0a0; hud.gd's floats transcribe to #8ff0a1. The spec records this itself and assigns the fix to the next hud.gd colour-block touch (follow-up job B). No action.
- **N12. The 6.0 ms figure could carry its source (OBSERVED, Qwen; chair downgrades).** ui_spec.md 7.4 states 6.0 ms frame median after #220 against R116's recorded 6.9 ms. The spec's own summary line attributes the figure to #220, and the board record for #220 (PR #223) reports the 6.0 ms median, so there is no contradiction; citing the bench207 README in 7.4 would make the number traceable from the spec alone.
