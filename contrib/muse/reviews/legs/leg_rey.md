Scope read: the four PR net diffs against their bases (GitHub API file lists and patches), the capture bats in full, the shared fx files at each PR head and at main via a local clone, and real merge tests (git merge-tree) of each PR against current main and of each pair against its own merge base. Heads pinned Nov 25, 2026: 2007 at 16bc0005dc7dddd7d29d2119aeefcc86e85b31e2, 2049 at 838263aed0b6d2a4948a21b282170f4448f724f8, 2021 at 207f5d71c00245cc3558bb8c5fa704dabeaa0c32, 2055 at d987c0536f1f54d12eca3e02c4b39b2254826128. Current main 3629e733.

## Findings

1. BLOCKING, OBSERVED. Sprite kind 8 is claimed twice. PR 2049 makes it the shared spark: godot/fx/fx.gd:813 at 838263ae, "const SPARK_KIND := 8", and reroutes thrown streaks into the spark path at fx.gd:822, "if kind in [1, 7, SPARK_KIND]:". But kind 8 is already the Eclipse (deathless) smoke sprite in godot/fx/fx_ship.gd, on main (fx_ship.gd:2623, "if faction == \"deathless\": color = Color(0.055, 0.025, 0.09); kind = 8"), kept by 2049's own branch (fx_ship.gd:2523, same line), and used again by 2007 with a new tint (fx_ship.gd:2571 at 16bc0005, "\"deathless\": smoke = fac.damage_glow * 0.18; kind = 8"). If spr() and the spark path write kind into the same sprite buffer, one of the two effects renders with the other's mask. Fix: 2049 moves SPARK_KIND to a free number (2021 already reserved 29 for its glob the same way) and adds a check that no fx_ship emitter uses it.

2. BLOCKING, OBSERVED. PR 2007 and PR 2049 conflict textually in eight files when merged against their own merge base (git merge-tree): godot/fx/fx.gd, fx_death.gd, fx_death_beats.gd, fx_ship.gd, fx_weapons.gd, faction_looks.json, godot/fx/test/death_variety_1586_check.gd, tools/pc/jobs/look_bench.bat. These are the same functions, not neighbouring code: both rewrite the death and hit recipes. They cannot both land without a manual resolution pass, and the resolution is design work, not clerical work, because of finding 1. Fix: merge 2007 first, then have 2049's owner resolve the spark work on top, re-running both PRs' fx checks on the merged tree.

3. HIGH, OBSERVED. None of the four merges cleanly into today's main (3629e733, git merge-tree): 2007 conflicts in godot/bench/look_bench.gd, godot/fx/faction_looks.json, godot/fx/fx_ship.gd; 2049 in faction_looks.json; 2021 in godot/fx/fx_breach.gd and fx_shaders.gd; 2055 in godot/bench/look_bench.gd, godot/render/ship_view.gd and godot/render/squadron_wing.gd. Separately, the heads are not all green on their own: 2021 at 207f5d71 fails nearly every Godot check on its own head; 2007's retry head 16bc0005 passes the four Godot game checks (the death-plane failure Artoo flagged at the old head 43660615 is gone) but still fails "Standing checks (rules, text, saves)", so its "All checks" is failure. 2049 and 2055 are fully green. These are pre-existing states, not combination effects, and the review must not be treated as merge evidence for 2021 or 2007 until their own heads are green.

4. HIGH, OBSERVED with INFERRED consequence. The sprite kind number space is edited by three PRs with no shared registry. Beyond kind 8: 2049 also reroutes kind 7 into the spark streak path (fx.gd:822), while 2007 assigns kind 7 to Hegemony fire and to non-organic vents (its fx_ship and fx_death hunks), and 2021's godot/fx/fx.gd:760 at 207f5d71, "const SMOKY := {3: true, 7: true, 8: true, 15: true, 20: true, 23: true, 27: true, SH.BIO_CONTACT_GLOB: true}", treats kinds 7, 8 and 20 as smoke for its status work, while 2007 assigns kind 20 to Chorus hatch and vent sprites. Inference: after all three land, the same kind number means spark to one system, fire or vent to a second, and smoke to a third; whichever system reads the buffer last wins, per effect. Fix: one kind registry comment block in fx.gd owned by the Board, each PR's numbers entered before merge.

5. HIGH, OBSERVED. PR 2021's capture launcher breaks against PR 2007's launcher. tools/pc/jobs/wave2b_run4.bat at 207f5d71 sets "LB_MOMENTS=res://bench/look_moments_1693_run4.json", a Godot path. PR 2007's capture check requires a real file: contrib/codex/issue-1991/capture.bat runs "if not exist \"%LB_MOMENTS%\" exit /b 2", and 2055's capture bat was explicitly written around that behaviour (its comment: pass a real Windows path in LB_MOMENTS because the #2007+ launcher checks `if not exist`). So 2021's run-4 captures fail the existence check once 2007's launcher is the one on the Board PC. Fix: 2021 passes the Windows path to the moments file, like 2055 does.

6. MEDIUM, OBSERVED. Three of the four capture bats do not pin AFTER to a full commit SHA by default. 2007: "if not defined LB_AFTER set \"LB_AFTER=origin/codex/issue-1991\"". 2049: "if not defined SPARK_AFTER set \"SPARK_AFTER=origin/codex/issue-2018\"". 2055: "if \"%AFTER%\"==\"\" set \"AFTER=origin/neon/issue-2042\"" and BEFORE defaults to "origin/main". A branch ref moves, so a default capture does not prove which code was photographed. Only 2021 enforces it: wave2b_run4.bat validates that AFTER is exactly 40 hex characters. All four pin BEFORE to a full SHA. Fix: default AFTER to a full SHA in each bat, or fail when no SHA argument is given, following 2021's pattern.

7. MEDIUM, OBSERVED conflict, INFERRED consequence. godot/fx/faction_looks.json is edited by both 2007 (damage_glow retune, +2 -2) and 2049 (+1 -1, plus a _fields rewrite noting Eclipse shed sparks use damage_glow). 9. LOW, INFERRED. Eclipse acid colour is a silent-revert hazard. 2021 rewrites the acid colour helper so deathless returns fac["damage_glow"] (godot/fx/fx_ship.gd:1908 at 207f5d71, "\"deathless\": return fac[\"damage_glow\"]"), replacing a hardcoded green, and its status_fx_check asserts the result is violet (blue greater than green). 2049's branch still carries the old line (fx_ship.gd:1886 at 838263ae, "return fac[\"damage_glow\"] if faction == \"deathless\" else Color(0.5, 0.9, 0.2)"). The two edits do not textually collide (the pair conflicts only in fx_weapons.gd), so nothing forces a resolver to look; a careless resolution or a later rebase of 2049 could restore the green without any conflict marker. Fix: whichever lands second, grep the merged fx_ship.gd for "0.5, 0.9, 0.2" and require it absent.

10. Merge order (recommendation). Gate: each PR green on its own head first (2021 and 2007 are not). Then: 2021 first (smallest fx footprint; its only fx.gd change is the SMOKY line), then 2007 (faction colour work), then 2049 (the spark rewrite resolves on top of 2007 and must move SPARK_KIND as part of that resolution), then 2055 last (largest shader and render churn; already conflicts with main in ship_view.gd and squadron_wing.gd). After each merge, the next PR's own fx checks re-run on the merged tree before it lands.

Shield blocks and the shield pool: no textual clash found in the four diffs. 2049 adds a check asserting quiet shield blocks (godot/fx/test/shared_spark_check.gd), and the shield_hit call sites in the shared fx_weapons hunks are unchanged context in both 2007 and 2049. Whether the combined build keeps shield blocks quiet at runtime is not proved by reading; it needs the merged build's checks.

Biggest risk in one line: the four PRs share one unregistered sprite-kind number space, and kind 8 (with 7 and 20 behind it) already means two different effects to two different systems before any merge starts.

Not checked: the merged build itself (no combined tree was built or run); runtime look of any effect; Windows capture execution on the Board PC; PR 2021's failing checks beyond their names and states; godot/fx/fx_pool.gd and other files only one PR touches.
