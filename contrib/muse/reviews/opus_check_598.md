## The wiring, checked end to end

1. ROUTING: the three places agree. work_issue.bat maps the arm kimicode to the model id kimicode/kimi-for-coding (and documents the fourth arm in its usage line); opencode.json defines provider kimicode on @ai-sdk/openai-compatible with baseURL https://api.kimi.com/coding/v1, apiKey {env:KIMI_CODE_API_KEY}, and the model kimi-for-coding. The plan host is the only URL the arm can reach in the real config.
2. KEY HANDLING: the key is saved by kimi_code_key.bat through setx as a user environment setting, with the variable cleared after; the PR writes the key to no file, log or report (the ps1 header's "never written to any file" still holds). In work_issue.bat the key is loaded for every real run, and the kimicode arm checks its own key before the clone step and fails closed (exit 3, a result.txt line naming the saver to run) when it is missing; the goto :clone then skips the DeepSeek and Moonshot key gates for this arm only, which is the correct scoping. One cosmetic point: the failure message says run KIMI_CODE_KEY.bat while the file is kimi_code_key.bat; Windows does not care, and neither does the runner.
3. THE PLAN'S SHAPE: Arm-Info gives kimicode the plan's models URL and bal = $null. The chair grepped the whole ps1 at head: the balance field is read only inside the balance mode, and the PR's guard there writes "plan (no balance)" and exits 0 before any request, so no null URL is ever called and a kimicode run's balance line will read exactly that. Keycheck probes the models URL, which this arm supplies; that is the "keycheck on the plan's model list" the commit message claims.
4. THE DRY RUN: the bat's dry setup sets all three keys to "dry" (kimicode's included) and points OPENCODE_CONFIG at the mock, whose kimicode stand-in routes to the local mock server at 127.0.0.1:8765. A dry kimicode run therefore exercises the arm end to end against the stand-in without touching the plan or the real key, subject to condition 1.
5. SAFETY AND SCOPE: the opencode.json permission block is reformatted (one pattern per line) with no change in substance: bash allow-all still carries the same denies (git push, git commit, git -c, recursive deletes, Remove-Item), and the new provider sits under the same permissions. On scope: Ryan closed the Kimi reviewer subscription question on Nov 9, and this PR does not reopen it. It adds a workhorse coder arm under the runner's rules, records the plan and the single head-to-head in RULEBOOK 2.6's seats text, and gives Kimi no council or reviewer seat, no default, and no preference. The distinction the Nov 9 ruling drew is kept clean.
