## Notes

1. The strike line's status, for the record. "His fleet is coming: your next fight is his." is still raw in both builds (campaign_run.js:81; campaign_ui.gd:747). The chair verified it is captured verbatim in issue #282's Done-when item (1), sequenced to run after #280 merges, so it is tracked and is not a condition here. The #274 condition is therefore two-thirds discharged in this PR and one-third scheduled. One structural reason it survived: the line is drawn outside nemPanelData, so the scenario records that pin the panel data cannot see it, and no test renders a panel with a strike pending.
2. run_end is not line-identical beyond the new field. The JS payload (campaign_meta.js:283) also carries sector, mins and fleet; the Godot twin (campaign.gd:1491) emits only victory, abandoned, fac, stats and the nem record. The asymmetry predates #122 (this PR adds the nem field to both), the nem record itself is a true twin, and telemetry is excluded from campaign parity, so nothing breaks. The 122-8 phrasing "twins line-identical" should be read as applying to the nem record, not the whole payload.
3. The live escape counter has no clamp; the save rebuild clamps to 2 (campaign_run.js:390 against :292). Under the once-per-sector meeting rule the live counter cannot pass 2 in play, so this is an invariant held by game structure rather than by the counter itself. A Math.min(2, ...) inside nemEscape would make the two paths agree by construction.
4. Two test-strength gaps. The run_end check (nemesis_122_tests.js:143-145) asserts nemTelSummary's shape behaviourally but proves the emission itself only by regex over the two source files; it would pass with a broken endRun path. The Godot panel structural test slices _nem_panel only; the helpers that actually draw the new content (_nem_prior at campaign_ui.gd:788, _nem_lessons at :783) are outside its slice. Relatedly, check 122-6's CI test asserts marker strings exist in the scenario files; the line-identity proof is run_nem_scenarios.sh, which joins CI only with #264 (PR #283, the next check in this queue).
5. The return line asserts a meeting the data never checks (INFERRED reachability). nemPanelData derives the return line from the assignment alone and prints "you met him in sector I.", while nemStatus, in the same function family, has a "never met" outcome for earlier hunters. If a sector can end with its hunter unmet, a returning hunter would be announced as met. The pack does not settle whether that can happen (the clock text promises a meeting at the latest before the rest stop); one met check in the derivation closes it either way.
6. The logic-versus-drawing split is partial, which is fine for R137 but worth naming. nemPanelData carries the new content; the card's traits, weaknesses, clock dots and strike line are still read in the drawing layer in both builds, and the Godot panel computes its Fed and Honed notes in the panel rather than reading D.compound. The twin evidence ("the panel data both UIs draw") therefore covers the new blocks, not the whole rendered card.
7. The two signature paths that pass no commander (battle.js nemSig; the Godot B.nemSigs loop at campaign.gd:3067-3068) attribute by call order: both resolve to nemActive() and are correct because of where they run (during the meeting; before nemAfterBattle and before any sector advance). The battle record carries no commander identity, so a future reordering would silently retag signatures, the A4 class of bug this series has fixed once. Every campaign call this PR touched passes its commander explicitly.
8. nemStatus tests scars before beaten, so a commander carrying both would read "escaped, scarred Nx" rather than "beaten, withdrew" (INFERRED). The chair could not find beaten's setter in campaign_run.js (it sits in the battle layer, outside this check's sources), and the priority arguably prefers the more informative fact. Recorded so the order is a decision, not an accident.

## Verified clean

- Signatures (122-1): nemSignature(kind, N0) files the list entry and the telemetry event under the given commander, else the active one (campaign_run.js:306); lists cap at 40, oldest dropped; the suite includes a test signing a commander who is not active.
- Escapes (122-2, 122-9): the only nemEscape calls are the flee branch and the flagship-withdraw branch (campaign_run.js:360, :363), and nemEscape itself refuses sector 3 and later (:390). The revive branch (:361) does not call it; deaths and losses never count. The counter lives only on RUN.
- The rebuild (campaign_run.js:292): scars have exactly three sources in the code (fled :360, revive :361, flagship :363; chair grep over the head file), so scars minus one for a revived commander is exact apart from the disclosed sector 3 flight, whose scar the rebuild cannot date. It runs only when the field is absent, so it cannot re-derive over a stored value, and its cap of 2 matches the counter's structural maximum.
- Fed isolation (122-3): nemFeedLosses reads the active commander and returns early unless his behaviour feeds (:384); nemCompound returns a counter only for a feeds faction (:391); riches and honed are never re-counted; the two counters cannot move each other.
- Panel data (122-4, 122-5): the current card is the active commander; Earlier hunters derive in story point order from the assignment, exclude the current commander, take their outcome text from nemStatus, and still list under a dead current hunter in both panels. The return line is built inside nemSay (:405); nemStatus is pronoun-free; lessons are read from each commander's own object and cannot cross over.
- The claimed pronoun fixes: the clock-full message through nemSay (campaign_run.js:316), with a test driving a Chorus, a female raid commander and a male and asserting the swapped forms; the modal's adaptWhy arrives swapped in the modal data (campaign.gd:2909); the Godot Fed and Honed notes wrapped (campaign_ui.gd:753, :762).
- A screened claim, recorded because it was checked and failed: the suggestion that the return line could name two sectors ("sector I and II") cannot happen. drawNemAssign (campaign_run.js:260-262) draws the second hunter different from the first and the third different from the second, so one faction holds at most slots 1 and 3, and holding slot 3 makes it the current hunter, excluded from both lists. The sector lists therefore never hold two entries.
- RUN.nem: nothing in this PR disturbs the maintained alias; the new code resolves commanders through nemActive() like the rest of the campaign.
