## 5. Design facts (from the assignment synthesis, ruled under R85)

The draw (synthesis section 1): at run start, one hunter faction per story point, drawn from the five non-player factions, no consecutive repeats. SP1: uniform from the five (1/5 each). SP2: uniform from the five minus the SP1 hunter (1/4 each of the remaining). SP3: uniform from the five minus the SP2 hunter (1/4 each). Stored as RUN.nemAssign = [H1, H2, H3] (name suggested; Opus owns the final field name). No cross-run balancing state; each run independent.

Marginals are exact, not approximate: for every player faction and every story point, every non-player faction has probability exactly 1/5 and the player's own faction exactly 0. Pr(H2 = H1) = 0, Pr(H3 = H2) = 0, Pr(H3 = H1) = 1/4. Expected hunts per faction across the full 6 player factions x 3 story points set: exactly 3 each.

Chair enumeration (synthesis section 5; a faithful draw simulation in Python, not the game code; 20,000 runs per player faction, 120,000 runs): hunts per faction out of 360,000 slots were Glasswrights 60,051, Hullbreakers 60,052, Crusade 59,919, Hegemony 60,113, Chorus 59,906, Eclipse 59,959, against an expected 60,000 each. Largest deviation of any single matrix cell from 0.200 was 0.0054. Per run, 74.9 percent of runs presented three distinct hunters and 25.1 percent presented two (the SP1 hunter returning at SP3), matching the analytic 1/4.

Registry and identity (synthesis section 2): one commander per hunter faction per run, created lazily when that faction is first drawn, using the existing newNemesis(fac) identity logic. The container is a registry keyed by faction; the active commander for sector k is the registry entry for RUN.nemAssign[k-1]. State attaches per commander, not per run: weaknesses and revealed set; adaptations (per commander, per run, reset at run start); scars and epithets; debrief lessons. An escaped SP1 commander who returns at SP3 carries his scars. Sector 3 deciding fight: the SP3 commander's flagship death ends him; SP1 and SP2 commanders not drawn at SP3 are simply absent.

Clock (synthesis section 2): NEM_CLOCK = 4 stays a single run-level accelerant. Its pace is read from the active commander's faction beh.clock (Eclipse 0.5, Crusade 1.5, others 1.0). A strike brings the sector's assigned meeting forward inside the sector; it never changes the hunter and never creates an extra meeting.

Meetings and teaching (synthesis section 4): the once-per-sector meeting stands, enforced at nemNodeIs with the active commander resolved from the assignment; the per-commander met flag is what enforces once-per-sector per commander. Debrief teaching on a lost meeting attaches to the commander met. The clash check (an adaptation may not directly counter a REVEALED weakness) is unchanged in rule and now runs per commander on that commander's own revealed set; the check is not duplicated into telemetry.

Telemetry (synthesis section 4): nemSignature keeps its event schema and per-commander capped list, tagged with the commander's faction. The escape counter is per run (counts commanders who escaped, at most two per run: SP1 and SP2). The compounding counter is per commander where the behaviour is commander-specific (Chorus growth is the named example). The two counters are not merged.

Run 5 finale (synthesis section 4, R85 Q4): no special rule; the run 5 finale meeting is the SP3 meeting of that run under the same draw.

Behaviour packages (synthesis section 4): unchanged. All six NEM_FAC[fac].beh packages stay attached to their hunter faction: Hullbreaker raids, Glasswright duels and returns upgraded, Chorus grows from the player's losses anywhere, Eclipse never retreats and returns once after death in sector 3 only, Crusade duels the flagship, Hegemony reinforces in round 3.

## 6. Code state (verified from main, Nov 5 2026; line numbers as of that read)

RNG (core.js:2-9): seeded mulberry32. `let RNG_S` holds the state; rndSeed(s) sets it; rnd() advances it; pick and shuffle consume it. Comment at core.js:2: each battle reseeds from B.seed, so a seed plus the same moves replays a fight. Everything at run scope (map generation, rewards, the Nemesis identity) consumes the same stream in call order.

Current Nemesis code (campaign_run.js), all written against the single RUN.nem:
- newNemesis(fac0) at :250: fac defaults to RUN.foes[3], else a pick from RUN_FACTIONS minus the player's faction. Identity: name via nemName (:249, pre/post pools, never an ADMIRALS name), title, persona, two traits, portrait 'nem_<fac>_1..6', two weaknesses; the weakness pool excludes counters to the commander's own traits (clash map at :252: slow counters swift, board counters boarders, ion counters shielded) and excludes 'anchor' for factions that cannot flee or that revive.
- NEM_CARRY at :256: the field list carried across an identity rebuild: weak, revealed, adapt, clock, met, beaten, scars, dead, strike, seen, loot, riches, fed, honed, held, revived, gloat, last_beat.
- nemOldFac(old) at :258 and ensureNemesis() at :259: if RUN.nem is missing or lacks a persona, a new identity is built and the NEM_CARRY fields are copied from the old object; older saves are normalised in place (last_beat from beat, gender field g, scarKinds). This is the existing old-save migration surface the redesign's migration must stay consistent with.
- nemGender (:267), nemPr (:268), nemSay (:269): nemSay swaps pronouns (he/his/him and capitalised forms) to the commander's gender set; male or unset gender returns the text unchanged.
- nemFull (:270), nemReveal (:271: reveals the first unrevealed weakness on the active single commander).
- nemSignature (:273): pushes the kind onto N.signatures (capped at 40, oldest shifted out) and emits a telemetry event tel('nem_signature', {fac, kind, sector}).
- nemWarnLine (:274), nemBeh (:278: the active commander's NEM_FAC[fac].beh), nemClockAdd (:280: step scaled by beh.clock, clamped 0 to NEM_CLOCK at half-step rounding; at full clock with met < sector and no strike pending, sets strike and calls nemStrike), nemStrike (:283).
- nemNodeIs (:290): false if no commander, dead, already met this sector (N.met >= RUN.sector), or the node is not battle/elite; true if a strike is pending or the node column is within the last three columns of the map.
- nemBattleCfg (:291): the battle-facing snapshot (gloat, honed, beaten, name, title, fac, persona, traits, weak, revealed, adapt, scars, fed, riches, last_beat, g, and met derived as beaten + scars > 0).
- nemAdapt (:294): once per sector (Chorus also after every meeting, via the adaptFast behaviour); cap formula at :294 uses RUN.sector and, for fast adapters, beaten + scars; reads RUN.nem.seen; the clash check blocks an adaptation that counters a revealed weakness.
- nemAdaptName/Desc/Why (:300-302), nemScar (:304), nemAfterBattle (:306): sets N.met = RUN.sector, clears strike, resets clock to 0; on a win increments beaten, reveals a weakness, and branches: fled (scar 'fled', signature 'flee', raid gains riches, duel gains honed), flagship dead in sector 3 or later with revive behaviour and not yet revived (revive once, N.met set back to sector - 1), flagship dead in sector 3 or later (dead), flagship dead earlier (scar, escapes; comment at :311 records R49: before the last sector every rival withdraws like this). On a loss: clock set to 1, gloat set, found weaknesses merged.
- nemPanel (:72): renders RUN.nem only; shows clock dots against NEM_CLOCK, traits, weaknesses (revealed named, unrevealed as 'unknown'), adaptations, last_beat memory line, behaviour lines (fed count of 8 with hull bonus, loot and held item return language).

Known traps (state these in your report and design checks that catch them):
- RNG stream coupling: the assignment draw consumes the run RNG at run start. Every downstream consumer (map, rewards, identity rolls) then draws from a shifted stream, so existing golden and scenario outputs change even if behaviour is correct. Checks must distinguish "goldens re-pinned because the stream shifted" from "behaviour changed": the scenario invariants (revive once, death in sector 3, feeding cap) must hold before and after, while exact canonical lines may need re-pinning. A check that only compares canonical lines cannot tell the two apart.
- Lazy creation order: commanders are created when first drawn, not at run start, so identity rolls (name, persona, traits, weaknesses) consume RNG at different points depending on the draw. A check that assumes all identities exist at run start is wrong.
- The draw itself: SP2 excludes the SP1 hunter and SP3 excludes the SP2 hunter only (SP3 may equal SP1). An implementation that excludes both previous hunters at SP3 (sampling without replacement) passes the marginal checks at SP1 and SP2 and fails the SP1-return rate (0 instead of 1/4). The enumeration check must measure the return rate directly, not infer it.
- Sector vs story point: the assignment is indexed by story point; sectors and story points are related but the met flag, the clock and nemAfterBattle all key off RUN.sector. Checks must pin which index the registry resolution uses, from the issue text (active commander per sector resolves from the assignment).
- Old saves: a save written by the current build has RUN.nem and no assignment or registry. Migration (issue 120 Done-when): the existing RUN.nem becomes the SP-current entry. Checks must cover: a mid-run save (sector 2, commander met once, clock part-full, adaptations present) loaded under the new build, and the pre-persona save shape already exercised in nem_scenarios.js scenario 8.
- Parity drift: the same rule lives in campaign_run.js and campaign.gd, and the oracle copies under godot/campaign/test/oracle/ are copies, not links; a fix applied to the browser file without re-copying oracles passes browser tests and fails parity later. Checks should include the oracle re-copy and the table re-export as explicit steps.
- Text: nemSay only swaps male pronouns; a NEM_VOICE line written with feminine or neutral pronouns baked in will not be corrected at runtime. Chorus lines must carry no gendered pronouns at all and no song or choir words. Eclipse flee must be empty AND the code path must never call it (Eclipse never retreats; nemAfterBattle's fled branch must be unreachable for a revive faction, as the current weakness-pool exclusion at campaign_run.js:252 already implies).
