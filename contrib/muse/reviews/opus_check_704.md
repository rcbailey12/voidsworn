## Conditions

1. The balance pack is absent from the PR body. The Board's note on issue 41 (Nov 14, 12:40 CST) says the rules change touches battle.js and the Godot rules, so the balance pack goes in the PR body. The body carries the runner's check log, run stats and changed-file list, and the runner notes the agent left no final report. The balance reasoning exists only as code comments. Unanimous across the council; DeepSeek grades it BLOCKING. The author or the Board appends the pack, or the Board waives the requirement on the record.

2. The prize screen's Add path bypasses the ripped rule (DeepSeek raised it; chair verified the mechanism in the base code at 6501c736, unchanged by this PR). ACT.prizeConfirm in campaign_run.js adds a kept prize with newShip(p.tpl), sets name and hull percentage, and pushes it to RUN.fleet; nothing sets ripped, and prizePlan's only gate is factionGate, which has no voidsworn entry. So if a battle prize offered to a Crusade fleet is a Hegemony or Eclipse hull, choosing Add fields it with its network intact (it can anchor, sync, and feed the Archive legion count), at no price, from run 1. The PR's prize test asserts only that prizePlan still returns an add row with ransom and strip values; it never exercises prizeConfirm. Board to rule one of: (a) prize generation can never offer these hulls to the Crusade (show where that is enforced), or (b) the keep path sets ripped for captured Hegemony and Eclipse hulls, with the run gate and price treatment the Board wants. The Godot prize flow was not separately read; parity is assumed, not verified, on this point.

3. Captured stock ignores the unlock progression (DeepSeek; chair verified the normal-stock gating in the same function). Normal yard stock gates the carrier, battleship and dreadnought hulls behind META.unlocked (u_carrier, u_battleship, u_dread); the captured draw is a uniform shuffle of all seven prizes from run 3, so a run 3 yard can offer the cp6 Dominion dreadnought or the cp4 cruisers before the matching unlock. The command point cap still applies at purchase. Board to confirm the bypass is intended for prizes, or gate the captured draw the same way.

## Chair verifications and notes

- Flash's BLOCKING (the regenerated Godot tables might lack the new entries) is closed: the rules.gd diff adds CINDER_PRIZES and CINDER_FIRST_RUN to the required tables list, campaign.gd loads both from the tables, and the runner log in the PR body shows the Godot cinder_prizes_test passing against the regenerated tables, which it could not do with the entries missing.
- DeepSeek's price condition is refuted on mechanism: data.js sets cost0 only when a faction price multiplier actually inflated a hull's cost (the pricing loop assigns cost0 in the same step). Hegemony is the 1.0 baseline, so its prizes have no cost0 and their cost already is the base; the Eclipse prizes carry cost0 from their inflation step. capturedHullPrice therefore prices all seven off base: picket 70, interdictor 130, vanguard 250, dominion 370, mote 70, jackal 130, harvester 250, before the yard multiplier. The tests pinning only some of these is a coverage note, not a pricing risk.
- DeepSeek's Godot crash framing is downgraded: campaign.gd's capturedHullPrice lookup is guarded (jt(TB.FAC_PRICE.get("voidsworn")) with a 1.0 fallback), so a missing table degrades silently rather than crashing. The underlying point stands as a NOTE, raised independently by Qwen and DeepSeek: FAC_PRICE is not in REQUIRED_TABLES, so load-time validation does not assert it.
- Repeat purchase from one yard (raised by Flash and DeepSeek) is consistent with existing yard behaviour: normal hull stock is not consumed on purchase either; only modules use the sold list. None of the seven prizes is a unique or boss hull (chair verified in data.js at the PR head), so the captured path's missing uniqueness check is inert today. NOTE only; it would matter if a unique hull joined CINDER_PRIZES.
- syncLose's surviving-hull log check lacks the ripped exclusion in battle.js (DeepSeek, chair verified in the diff): cosmetic, the log line can claim sync is lost while only a ripped Hegemony hull remains. NOTE.
