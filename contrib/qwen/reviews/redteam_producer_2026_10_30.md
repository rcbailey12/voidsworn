Producer and Scope Realist Audit: Voidsworn, "Embers of the Hollow Sun"
Findings, ranked by severity for this seat
Finding 1: Forty regression-tested defects have no scheduled fix and no assigned home
OBSERVED: The findings-to-tests ledger reads "8 PASS / 40 FAIL at the pin" and the register confirms "failures are correct regression tests against unfixed defects." OBSERVED: The browser build is "frozen to break fixes only since Oct 26, 2026." OBSERVED: The Godot migration sequence is "rules parity checks, one playable battle, then the full run, effects pass, cutover."
INFERRED: The 40 failing tests name real defects that the frozen browser build will not receive and the Godot tree has not yet reached. Rules parity is the first Godot milestone; these 40 fixes sit downstream of it. No artifact in the pack assigns them to a wave, a gate, or a parity checkpoint. The tests exist, the defects exist, and the plan to close them does not. This costs the game a known-degraded playable state for the entire duration of the Godot build-out, and it costs the team 40 open items that will compete with new Godot work for attention at every milestone.
Finding 2: The review apparatus is outproducing the build it audits
OBSERVED: The evidence base includes "Ten Oct 29 syntheses, plus the Oct 27 and Oct 28 programs." OBSERVED: Savings-pass waves produced "a patch pack and addendum" and "a findings-to-tests ledger with 48 regression tests, and importer fixtures." OBSERVED: Content assemblies total 216 tree texts, 33 event variants, 41 Nemesis lines, 16 tutorial tips, and 30 firstrun framing units. OBSERVED: The game being audited is "8,947 lines of JS across the root files."
INFERRED: The review and documentation output (ten syntheses in one day, two multi-day programs, five savings-pass deliverables, 336 content units, a 3D brief red-teamed twice) dwarfs the codebase it covers. The Opus handoff states plainly: "This document assigns nothing. It does not sequence implementation work, set priorities, or order builds." The review apparatus generates findings, amendments, and content, but the pack contains no artifact that converts that output into a sequenced build plan. The cost is calendar time spent producing audit documents that the implementation schedule cannot absorb.
Finding 3: The Godot critical path is serial, long, and gated on an unmeasured budget
OBSERVED: The migration order is "rules parity checks, one playable battle, then the full run, effects pass, cutover." OBSERVED: The 3D brief states the real budget "gets set by the effects-pass performance budget item using PERFCAP on Ryan's PC." OBSERVED: Steam is "deferred until after the Godot build is played; no Steam Deck work."
INFERRED: Five serial milestones separate today's frozen browser build from a playable Godot run, and a sixth (Steam) sits behind all of them. The effects pass, fourth in the chain, cannot be scoped until a PERFCAP measurement that has not happened produces a number. Every day the performance budget goes unmeasured is a day the effects pass cannot be estimated, which means the cutover cannot be dated, which means Steam cannot be dated. The cost is an unbounded schedule: the team cannot say when the Godot build is playable because a middle dependency has no measurement yet.
Finding 4: The save importer is a named BLOCKER with fixtures but no implementation
OBSERVED: The claims register states "saves BLOCKER without the importer (fixtures now built and filed)." OBSERVED: The save format is a single JSON envelope: "One envelope holds almost everything." OBSERVED: "Id stability is load-bearing for this save format." OBSERVED: "There is no chain of per-version transforms."
INFERRED: The fixtures define what a valid save looks like, but the importer that converts browser saves to Godot saves does not exist in the pack. The save schema has no versioned migration chain beyond v1-to-v2, so any structural change in the Godot port has nowhere to hook a transform. If the Godot save structure diverges from the browser JSON, every existing player's run and meta-progression are at risk. The cost is that cutover, the final migration milestone, is blocked by a component that has a test harness but no code.
Finding 5: The content pipeline is running ahead of the implementation that consumes it
OBSERVED: "216 tree texts (tiers 1-3 assembled)" plus 33 event variants, 41 Nemesis lines, 16 tutorial tips, and 30 firstrun framing units are on file. OBSERVED: The Godot tree is at "rules parity checks." OBSERVED: The Eclipse battleship entry has "d_meridian vs d_wraith left to Opus."
INFERRED: 336 content units plus an unresolved ship entry are assembled and waiting, but the Godot build cannot display any of them until at least the "one playable battle" milestone, and most of them not until "the full run." Content that sits unimplemented for months rots: ids shift, balance passes change the context the text was written for, and the team must re-verify it later. The cost is rework. The 26-of-33 event free-exit pass rate means 7 events already need revision before they ship; the longer they wait for a build to run in, the more expensive that revision becomes.
Finding 6: A third silent weapon deletion confirms a data integrity pattern in a frozen build
OBSERVED: The register records a "third silent weapon deletion found Oct 30 (b_razor_s drops bioplasma undisclosed)." OBSERVED: The browser build is "frozen to break fixes only since Oct 26, 2026." OBSERVED: data.js holds "all game data: SHIPS, WEAPONS, MODULES, RELICS, EVENTS."
INFERRED: Three silent deletions of weapon data from ship loadouts is a pattern, not an accident. The build that contains the defect is frozen, so the defect ships. The Godot tree must either replicate the defect for parity or silently fix it, and the pack does not say which. If parity is enforced, the wrong data carries forward. If it is fixed silently, parity checks flag a false divergence. The cost is either a balance defect in the shipped Godot build or audit noise in every parity gate.
Finding 7: The Forward+ renderer decision rests on a single shipped-game data point
OBSERVED: The 3D brief states "Best shipped-game evidence is a SINGLE dev write-up, treat as a lead." OBSERVED: "No verifiable statistic exists for what shipped Godot games typically choose." OBSERVED: Forward+ was chosen "decisively" and "red-teamed twice" and "amended once."
INFERRED: The renderer is settled as a ruling, and I do not reopen it. But the effects pass is being scoped around Forward+ performance characteristics validated by one strategy game (ReBirth) on two GPUs. The brief's own audience floor is "RTX 3060" at 1080p. If Forward+ cluster budgets (512 shared elements for lights, decals, probes) prove tighter than the single data point suggests at 20-ship battle scale, the effects pass must be re-scoped after it is underway. The cost is a probable mid-pass re-plan on the longest serial segment of the Godot build.
Finding 8: The mobile detection layer misclassifies desktops and is frozen in place
OBSERVED: "G.mobile is computed once at load" and "A touchscreen 2-in-1, a small snapped window, or a tablet-class device at boot therefore boots as a phone." OBSERVED: The PC-only ruling is settled. OBSERVED: The browser build is frozen.
INFERRED: The ruling says PC only, and the performance audit recommends to "gate the whole branch behind an explicit phone build flag or delete it at the Godot cutover." But the browser build is the "playable truth today" and it is frozen. Any player on a 2-in-1 or a small window gets degraded settings, half-rate effects, and a 1024 shadow map with no in-game explanation. The cost is a subset of today's players experiencing a worse game than the build intends, with no fix path until Godot ships.
Finding 9: Three review rounds on one brief consumed time the critical path does not have
OBSERVED: The Godot 3D brief was "red-teamed twice (DeepSeek BRIEF HAS HOLES, Qwen objections chair-rejected), amended once." OBSERVED: The brief is one document among "Ten Oct 29 syntheses."
INFERRED: Two red-team passes and one amendment on a single brief means three full review cycles before the document was actionable. The chair rejected Qwen's objections, meaning the second pass produced no net change. In a schedule where the effects pass cannot begin until a PERFCAP measurement happens, review cycles on the brief that do not produce amendments are calendar time the critical path cannot spare. The cost is days of reviewer and chair attention spent on a document that was already sufficient after round one.
Finding 10: Three designer rulings depend on play data that cannot be collected until telemetry ships in Godot
OBSERVED: The telemetry spec exists because "three designer rulings end with 'revisit with actual play data.'" OBSERVED: "play data does not exist unless the build logs it on purpose." OBSERVED: The spec is a "Chair proposal for Opus to verify and implement." OBSERVED: The browser build is frozen.
INFERRED: The regroup tension ruling (0.0% bind rate in sims), the Nemesis snowball question, and the generational payoff question all await play data. The telemetry spec is written but not implemented. The browser build, which could collect data today, is frozen, and the spec targets Godot: "Local only: one JSON object per line appended to a file under user://." Three rulings that are marked ACCEPT or MEASURE remain unvalidated until the Godot build is playable, which is at least three serial milestones away. The cost is that design decisions at the core of the economy, the Nemesis, and meta-progression operate on sim data alone for the entire Godot build-out.
Verdict
The program's single most dangerous property is that its review apparatus, its content pipeline, and its measurement infrastructure are all running ahead of a Godot build that has not yet cleared rules parity; the critical path is serial, undated, and gated on a PERFCAP measurement that has not happened. The most important attack: 40 regression-tested defects have no scheduled fix, the save importer is a blocker with fixtures but no code, and no artifact in this pack converts any of the ten syntheses or five savings-pass deliverables into a sequenced, dated build plan. The team is producing excellent audit documents faster than it can build the game they describe.
Not checked
This seat could not judge: the actual runtime performance of the Godot tree (no profiling data in the pack); whether the 216 tree texts, 41 Nemesis lines, and 30 firstrun framing units are internally consistent or require the flagged story attack; the state of the Godot rules parity checks beyond their existence in the sequence; whether the Eclipse battleship resolution (d_meridian vs d_wraith) has downstream scope implications; the real cost in Godot implementation time of fixing the 40 failing regression tests; and whether the telemetry spec's event list is sufficient once implemented, since it has not been tested against a running build.
