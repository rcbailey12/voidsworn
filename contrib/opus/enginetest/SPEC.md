# A2 engine test: the shared spec

Plan: `contrib/opus/go-forward-plan.md`, phase A2. One scene, built twice: once in Babylon.js 8.20 (today's engine), once in Godot 4.7.2 (installed portable on Ryan's PC, `Downloads\voidsworn_test\godot\Godot_v4.7.2-stable_win64_console.exe`). Both builds follow this file exactly, so the comparison is fair. Neither build reuses the game's existing effects or shaders: Babylon gets no head start.

## Ships (six faction flagships)

All are standard glTF binaries in the same frame: x toward the bow, y up, z to port, length about 1.0.

| Faction | Ship | File | Source |
|---|---|---|---|
| Voidsworn | Ascendant dreadnought | `V1b_r_23.glb` | `hull2glb.py` from hulls_hi |
| Hegemony | Super-dreadnought | `H4_11.glb` | `hull2glb.py` |
| Corsair | Pyre-Barge v15 | `C19_51_shell.glb` + `C19_51_kit.glb` (two files, same frame, load both) | painted exports from the barge pipeline (assets/ships/C19_51/README.md); on the PC under `comfy_io\C19_51\v15\shell_painted.glb` and `kit_painted.glb` |
| Chorus | Bio-titan | `B16_23.glb` | `hull2glb.py` |
| Ithar | Ark | `I8_37.glb` | `hull2glb.py` |
| Deathless | Tomb-ark | `D22_23.glb` | `hull2glb.py` |

On the PC every file sits in `Downloads\voidsworn_test\enginetest\assets\`. In the repo the five converted ships are rebuilt with `python3 contrib/opus/enginetest/hull2glb.py CODE faction out.glb` (they are about 15 MB each, so they are not committed).

The barge's painted files come from Blender, whose glTF export already turns z-up into y-up, but the barge was built with its bow at -x. So rotate the barge 180 degrees about y, and its bow points +x like the others. Check by eye in the first screenshot: all six bows point the same way.

## Layout

- Scale every ship uniformly to a length of 24 units.
- Two rows of three, all bows toward +x.
  - Row 1 (z = +30): Voidsworn at x = -45, Hegemony at x = 0, Corsair at x = +45.
  - Row 2 (z = -30): Chorus at x = -45, Ithar at x = 0, Deathless at x = +45.
- Ship centres at y = 0. No board, grid or terrain.

## Background and light

- Background: `starfield_4k.png` in this folder (equirectangular, generated by `make_starfield.py`, same file in both engines), shown as the sky. It also gives a dim ambient term: ambient strength 0.25 of the key light, neutral colour.
- Key light: directional, from direction (x -0.45, y -0.70, z -0.55) toward the scene (so it comes from upper left, front), colour (1.0, 0.96, 0.90). Intensity: whatever makes the Hegemony hull (light grey) read near-white but not clipped in the close-up.
- Fill light: directional, opposite side (x 0.6, y -0.2, z 0.75), colour (0.55, 0.65, 0.85), 25% of the key.
- Tone mapping ACES in both. Exposure 1.0. Bloom: on, threshold about 0.8, moderate.
- Shadows: the key light casts shadows in both, one cascade set covering the formation, comparable resolution (2048 or 4096).

## Effects (built fresh, same spec, equal time box of about the same effort in each engine)

A loop every 2.0 seconds. Each ship, staggered by 0.3 s in the order above:
1. **Main weapon fire:** three bolts from the bow toward a point 60 units ahead and 10 units out to the side, faction colour (table below), each bolt a bright glowing streak about 6 units long, travelling 120 units per second, with a muzzle flash at the bow (0.1 s).
2. **Shield hit:** at 0.6 s into the ship's slot, a hit on the ship's port side. Voidsworn, Hegemony, Corsair and Ithar show a shield: a partial ellipsoid bubble around the ship flashing in the faction shield colour, fading over 0.5 s, brightest at the impact point. Chorus and Deathless have no shields: they show a hull hit instead (orange sparks and a small fire puff on the hull, 0.6 s).
3. **Explosion:** at 1.2 s into the slot, a fireball 8 units across at a point 12 units off the ship's starboard side: a bright core, rolling flame, 20 to 40 sparks, a smoke puff that outlives it (about 1.5 s total).

Faction colours (linear RGB), from the game's ships3d.js FAC3D:

| Corsair | (0.95, 0.22, 0.10) | (0.85, 0.16, 0.10) |

## Cameras (identical poses in both, so screenshots line up for the blind pick)

Vertical field of view 40 degrees in both.

- **Battle camera path** (benchmark): a 20-second orbit around the formation centre (0, 0, 0). Radius 150, height 70, starting at azimuth 200 degrees (measured from +x toward +z), turning 120 degrees over the 20 s at an even speed, always looking at (0, -5, 0).
- **Close-up** (stills only): camera at (+20, 14, +58) looking at the Corsair barge centre (+45, 0, +30).

Screenshots: battle camera at t = 5.0 s and t = 12.0 s, the close-up after 1.3 s of the effect loop (mid-explosion). Use the same frame times in both engines, driven by a fixed clock (not wall time) for the stills.

## What each build must measure and write

A command-line run that needs no clicking. Each run writes one JSON file:

```
{"engine": "godot" | "babylon", "renderer": "forward_plus" | "gl_compatibility" | "webgl2" | "webgpu",
 "width": 3840, "height": 2160, "seconds": 20, "frames": N,
 "avg_ms": .., "p99_ms": .. (the worst 1% of frame times, averaged), "max_ms": .., "fps_avg": ..,
 "load_s": .. (process or page start to the first frame with all six ships and the sky shown),
 "gpu_mem_mb": .. (engine's own counter if it has one; the PC job also samples nvidia-smi), "notes": ".."}
```

Runs on the PC (the job loops these): 3840x2160 and 2560x1440, for Godot Forward+, Godot Compatibility, Babylon WebGL2. The benchmark uses the battle path with the effect loop running, after a 3-second warm-up that is not counted. VSync off where the engine allows (Godot `--disable-vsync`; Babylon in Chromium with `--disable-gpu-vsync --disable-frame-rate-limit`), so frame time is real.

Babylon runs in Chromium through Playwright with the real GPU (the PC is an RTX 5080; launch args like fxshot.py's GPU mode, never the software `--use-angle=swiftshader` closeshot uses).

## Folders

- `contrib/opus/enginetest/godot/`: the Godot project (project.godot, scene, scripts). Run line: `Godot_..._console.exe --path godot --rendering-method forward_plus --resolution 3840x2160 --disable-vsync -- --bench out.json --seconds 20` (plus `--shots dir` for stills).
- `contrib/opus/enginetest/babylon/`: `index.html` plus `run.py` (Playwright: `python run.py --res 3840x2160 --out out.json [--shots dir]`).
- Both read ships from `../assets/` relative to the enginetest folder.
- `contrib/opus/enginetest/RESULTS.md`: the one-page result (written after the PC runs).
