2. Board check: open PRs, open issues and labels (gh api REST, never GraphQL). PC queue folders only when a PC job is running.
3. Check claims against the done-when, look at the shots. Read the PR's Artoo comments on its current head commit and settle each (verify against live main; evidence, not rulings; R295). Merge if good; hold what Holds lists; file a follow-up for anything the sweep finds. Outside-check conditions still open at merge become issues (the PR 680 form) or a line in the PR's FINDINGS row, so none rides on memory (Muse audit 706 finding 10).
4. Release the next job only to a live seat, one at a time. Before releasing, check it is not already queued or running.
5. Anything for Ryan goes under "Waiting on Ryan" with a pick and plain trade-offs. In an unattended run use one PushNotification, never AskUserQuestion.
6. Tell Ryan only when something lands or needs him: two lines and one image.
7. Rewrite this file, set "Running: no", commit straight to main (this file and FINDINGS only, docs-only exception), push with timeout 90. Stop.
8. One send_later check only when a job or a limit reset lands well before the next look. Never chain them.

## Known traps

- PC file writes through the bridge can report success and not land (Nov 15: gpu_go.txt). Use a fresh sandbox path per write, then stage the file back and read it.

- A Board push to a codex/, muse/ or work/ branch makes auto_pr rewrite that PR's text from the new commit message, dropping the worker's evidence and its closing line (Nov 15, PRs 702 and 714). Save the body first (gh api .../pulls/N --jq .body) and restore it with the Board's note added.

Copy .bat files from the working tree, never from git show (it prints LF; .gitattributes makes CRLF on checkout).
- A two-ship PC job runs one cmd per ship (stage 3 kept the first ship's CAMJ). A q_ file that waits blocks the serial queue: wait inside the started window instead. Never merge on a wait loop that timed out.

A PR that adds a test script adds its line (class headless or gpu). - GitHub failure emails that are not failures (found Nov 10 14:55 UTC): a pull request opened by auto_pr.yml is opened by github-actions[bot], so its `pull_request` run of checks.yml never starts a job and flips to 'failure' with zero jobs when the PR merges.
