1. Candidate verdicts

A. Authored hull variants: PRIMARY. This is the safest layer and the one already inside the project’s plans. It scratches the mech bay itch at the hull-choice level without opening a combinatorial hole: each variant is a discrete row with a cost and a faction-arc unlock, so the simulation can treat it as its own hull entry. Feel is moderate rather than deep, because the player is choosing a curated configuration rather than building one, but that curation keeps each chassis feeling distinct, which is the same reason BattleTech’s hardpoints keep different mechs from collapsing into one another. Fun comes from fleet composition and arc unlock timing, not pre-battle spreadsheet time. Balance cost is low: the existing 45-hull, 25-weapon, 13-module census already supports rows, and variants can be simmed beside base hulls. Build cost is low to medium: data rows, a variant selector, and possibly one alternate visual kit per hull, but no new hardpoint system.

B. Dock refits with a Nemesis clock cost: SECONDARY. This adds campaign pressure to tinkering, which fits the roguelite structure and the shipyard node already on the map. Feel is decent because a dock visit with a clock cost makes the refit feel like a real campaign decision, similar to managing a voidship at port in Rogue Trader. Fun depends entirely on tuning: if the clock cost is small, it is just a credit tax; if it is large, it punishes experimentation and pushes players toward one solved loadout. Balance cost is medium because a module plus one weapon pod is bounded, but the clock interaction needs its own simulation rows. Build cost is medium: shipyard UI, clock hooks, and Nemesis adaptation logic. This is a good optional pressure layer on top of A and C, not the core fantasy.

C. Flagship only layered customization: PRIMARY. This is the direct answer to the mech bay itch. The flagship is present in every battle, carries the admiral, accumulates scars, and anchors the Nemesis rivalry, so every pod, module, and section point is felt repeatedly. Feel is high because the player is not tuning a random hull; they are tuning the ship that represents them. Fun is high if the layers interact, for example a fast flanking section tune paired with a short-range pod and a defensive module, because the player is making a coherent combat identity rather than a stat block. Balance cost is bounded: one hull out of twenty, so the simulation can cover a small set of flagship configurations instead of every ship times every weapon. Build cost is the highest per hull: visual mounts for pods and modules, a customization UI, enemy AI that reacts to a changed flagship, and Nemesis adaptation that does not simply punish the player for customizing. But the cost is concentrated on one hull, which is why it is feasible.

D. Section tuning for every ship: LATER. The armour-allocation itch is real, and BattleTech’s mech lab shows that distributing armour points across locations is part of the attachment. But in Voidsworn critical hits are soft and temporary, with no permanent location destruction, so section tuning has less tactical bite than it does in BattleTech. Fun is a one-time puzzle: once the player finds the best allocation for a hull, the decision is solved and stops adding weight. Balance cost is low because it is a stat shift, but it still multiplies across every ship if applied fleet-wide. Build cost is low for the UI but higher for readable per-section visual feedback. It belongs later, and it works better as one layer inside C than as a fleet-wide system.

E. Full open hardpoint lab: REJECT. Feel is superficially attractive because it is the literal MechLab, but the cost is severe. Fun collapses into pre-battle spreadsheet time: the player is optimizing combinations outside the battle rather than making decisions inside it. Balance cost is the killer. The project’s balance process is simulation led, with about 19,500 bot battles as baseline and measured admiral win rates from 57 to 98 percent. Free-form loadout combinations cannot be exhaustively simmed, so the balance team loses the ability to say what a hull is worth. Build cost is enormous: every hull needs open hardpoints, visual mounts, AI responses, and UI. This is the one candidate that would make the game less legible and less tunable at the same time.

2. The central question

Yes with one condition. Flagship-only layered customization does enough of the mech bay job on its own only if the rest of the fleet still has authored identity through variants. The flagship can carry the deep fantasy, but it cannot carry the whole fleet’s texture.

The comparable game that proves one unit can carry the fantasy is Warhammer 40,000: Rogue Trader. The player has one voidship, and customization runs through prow weapons, port and starboard batteries, dorsal macrocannons, shield generators, armour plating, and a twelve-rank upgrade track with post abilities and flagship developments. The player feels ownership because every upgrade lands on the same vessel that appears in every void battle. The ship is not a menu; it is the character’s seat of power. That is the strongest argument for C. Starsector’s Deploy-Flagship-Only mod makes a similar case from the other direction: it turns a fleet game into a single-ship tactical game, but it needs three layered power systems to make that single ship viable and fun. One layer of customization is not enough; the flagship needs pod, module, and section tuning stacked, exactly as C proposes.

The comparable game where fleet-wide tinkering is the point is Star Traders: Frontiers. Ships are customized enormously, components are split by size rather than function, and the player rips out cargo spaces to fit a targeting module and a brig, or replaces a missile launcher with a navigation doodad. The player feels like a captain shaping a small fleet to a career, not like a pilot tuning one machine. BattleTech is a second counterexample in a different key: the mech bay fantasy is a lance-level fantasy, with each of twenty-five mechs heavily customizable in weapons, armour, heat sinks, and engines. If only one mech in the lance were customizable, the lance-building decision would feel thin. Voidsworn has twenty ships on the board, so a flagship-only system without authored variants would make nineteen of them feel like props. The condition is therefore not optional: pair C with A so the fleet has curated identity while the flagship carries the deep tinkering.

3. Interaction risks

My highest-ranked form is a hybrid of C plus A: deep layered customization on the flagship, authored variants on the rest of the fleet. The three worst interactions are below.

Nemesis adaptation to the player’s most used weapon kind. This is a real problem. If the flagship’s swappable pod lets the player lean hard into one weapon kind, the Nemesis will adapt to counter that kind, and the player’s customization choice becomes a trap. The player feels punished for using the system the way it was designed. The cheapest guardrail is to base Nemesis adaptation on fleet-wide weapon usage rather than the flagship pod alone, and to let section tuning, not pod swapping, be the player’s counter-adaptation lever. That way the player can answer the Nemesis by changing how the flagship fights without having to abandon the pod identity entirely.

Capture economy and strip and ransom. This is a real problem if custom parts can be stripped. If captured ships can yield modules or weapon pods, players will farm captures for customization parts, and the ransom and strip economy will inflate. The player feels incentivised to fight for parts rather than for territory or story. The cheapest guardrail is to seal custom-equipped captured ships: they auto-scrap for a fixed credit or material value based on the base hull, and they never return flagship-grade pods or modules. Ransom value should also use the base hull, not the custom loadout, so a lucky capture does not become a customization shortcut.

Hegemony flagship anchor. This is mostly a paper problem, but it becomes real if the anchor flag is exposed as a customization slot. Hegemony formation sync anchors on the flagship, and the faction loses formation sync without it. If section tuning can make the flagship so fast or so fragile that the anchor becomes a liability, Hegemony identity bends around the customization system. The cheapest guardrail is simple: the anchor flag is hull-fixed and never appears in the customization UI. Section tuning can move speed and armour points, but it cannot remove the anchor property. That keeps the faction’s named loss condition intact.

The lower-risk interactions are difficulty ramp, admiral identity, and faction identity. Difficulty ramp is a paper problem because C plus A is bounded and simmable. Admiral identity is a paper problem if modules grant only passive or triggered ship effects, never Command abilities; the cheapest guardrail is to tag Commands as admiral-exclusive. Faction identity is a real but manageable problem if the flagship pod pool is open; the cheapest guardrail is to filter the pod pool by the flagship’s faction weapon kinds, so a Hegemony flagship cannot casually become a bio or gauss platform.

4. Your hybrid

I would propose the Flagship Refit Bay plus Authored Variants. It is C and A together, not C alone.

What can be swapped. On the flagship only: one weapon pod, one module slot, and section tuning. The pod swaps one weapon kind within the flagship faction’s weapon pool. The module slot takes one existing module. Section tuning moves up to two points among prow, mid, and engine; each point trades armour or shield weight against speed or thrust. The three layers stack, so a player can build a fast flanking flagship with a short-range pod and a defensive module, or a slow anchor with a long-range pod and a shield module.

On every other ship: authored variants only. Each hull gets one or two pre-authored variants. A variant swaps one weapon kind and makes one stat trade, and it is unlocked through a faction arc. Variants are simmed as their own hull rows, so the balance process never has to guess what a variant is worth.

Where and when. Dock only, at shipyard nodes between sectors. No swapping mid-battle, and no swapping between fights unless the player is at a shipyard. This preserves the campaign rhythm and keeps the customization from becoming a between-battle spreadsheet.

What it costs. Credits for the pod and module. A major pod swap ticks the Nemesis clock, maybe one tick, so the player feels campaign pressure without being locked out of experimentation. Section tuning is free or cheap and reversible at the same dock, because it is the layer that lets the player answer the Nemesis without paying the clock again. Variants cost credits plus the faction-arc unlock.

What is explicitly not swappable. Hull core stats, the faction weapon trait (plasma stays a Hegemony trait, ion stays a lance trait), admiral Command slots, the flagship anchor property, engine type, shield generator type, and maximum armour per section. Section tuning moves points inside the existing envelope; it does not change the envelope. There is no free-form hardpoint placement and no cross-faction pod stealing.

Prototype scope. One flagship, three faction-legal pods, two modules, and two section-tuning points. Six authored variants across six hulls, one variant per hull, to test the fleet-wide texture alongside the flagship depth. That is enough to answer whether the hybrid feels like a mech bay or like a menu.

5. Sequencing

Decide or reserve now, before cutover.

The first now item is the save schema for per-ship customization state. Even if the system does not ship for months, the save format should be able to hold a flagship pod ID, a module ID, a section-point allocation, and a variant ID per hull. If the schema is not reserved before cutover, every future customization save will need a migration, and migrations get more expensive after players have runs in progress.

The second now item is visual mount conventions for the flagship. The art and rigging pipeline needs a named weapon-pod anchor and a named module socket on the flagship hull before cutover, even if no pod art exists yet. If the conventions are invented later, the flagship will need re-rigging and every existing visual variant will need rework.

The third now item is a simulation hook that can resolve a customized loadout into a row. The balance process must be able to ask “what is this flagship with this pod, this module, and this section tune worth?” without hand-building a special case. This is a small API reservation, not a full implementation.

The fourth now item is faction weapon pool tags, so the pod pool can be filtered by faction from day one. This is a data convention, not content.

What can safely wait. The customization UI, the actual pod and module content, the visual assets, the balance numbers, the enemy AI response to a customized flagship, the Nemesis adaptation logic, the authored variant content beyond the schema row, and the faction-arc unlock flow. None of these cost anything if they wait, because the schema and mount conventions are the only things that are expensive to retrofit. If the schema and anchors are reserved now, the rest can be built after cutover without painting the future system into a corner.

Overall verdict

The single customization addition I would make first is flagship layered customization, candidate C, because it is the one that directly scratches the mech bay itch and it is bounded to one hull out of twenty. The single addition I would never make is the full open hardpoint lab, candidate E, because it turns customization into pre-battle spreadsheet time and destroys the simulation-led balance process that the project depends on. C first, with A as its necessary fleet-wide companion; E never.
