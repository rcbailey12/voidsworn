# Outside Review of PR #1776: Planets V2 Cold-Load Fix (`69563a9d`)

**Verdict: 4 blocking issues before merge (confirmed in headless Godot 4.7.2 on Windows).** Commit `69563a9d` fixes the single-battle cold standalone launch (board maps now queue ahead of the 4K sky on an idle worker), but leaves multi-battle/title-showcase starvation, a FIFO cache-eviction map loss introduced by PR #1776's `request_*`/`result` split, a native Windows heap-corruption crash in `world_bake.gd:clear_static()`, and vacuous headless regression checks in `planet_v2_check.gd`.

**Direct answers to the four review questions:**

1. **Is it safe to queue maps inside the battle's `_ready` now (`world_bake.gd` joins deferred)? Any path where the request is refused or lost?**
   - **Queuing inside `_ready` itself works** on a clean startup: a main-scene `_ready()` probe (`p_c.tscn`) queued all 3 volcanic board maps while `root` was busy (`svc.is_inside_tree() == false`), attached `WorldBakes` deferred without error, and ran all 3 board maps before sky/moons (`exit 0`).
   - **Two broken paths remain:**
     1. **Lost map via FIFO `_cache` eviction (BLOCKING, finding #2):** `request_authored` / `request_bake` skips queuing when `_cache.has(key)` without pinning or refreshing FIFO order (`CACHE_MAX := 24`). When an earlier map finishes and calls `remember()`, it can evict a later map of the same set from slot 0 before `result()` runs; `result()` then returns `null` and `install_rocky`/`install_board` silently abandons the planet on its stand-in (reproduced live: `rel_img==null: true`).
     2. **Native crash if `clear_static()` runs before deferred attach lands (BLOCKING, finding #3):** `world_bake.gd:79` calls `_pending.free()` while `tree.root.add_child.call_deferred(node)` is still queued, crashing Windows with `0xC0000374` (`STATUS_HEAP_CORRUPTION`) even on immediate `quit(0)` (and `0xC0000005` after a frame).
2. **Can the urgent queue still be starved by the sky or a backdrop bake in another order (other seeds, a second battle, a reload)?**
   - **Single cold standalone battle (all 5 looks/seeds, idle worker): NO.** `battle.gd:601` (`board.build`) queues the full urgent map set synchronously before `battle.gd:622` (`world.build`) queues sky and moons.
   - **Title -> Quick Battle, Continue Run (reload), Sector Map -> Battle, or second battle: YES (BLOCKING, finding #1).** Freeing `showcase` or a prior `World` does not cancel `WorldBakes._active` or purge abandoned `_queue` jobs (`world_bake.gd:188`). An active 4K sky/backdrop bake still blocks urgent board maps; `battle.gd:547-549` awaits 2 frames on non-headless Windows before `board.build()`, letting `_process()` pop another abandoned 4K job into `_active`; and when `showcase` rolls `"planet"` (25% of title boots, `main.gd:406`), its remaining `urgent` board maps sit ahead of the real battle's urgent maps (`world_bake.gd:122`), putting up to 6x 4K bakes ahead of the cover.
3. **Do `planet_v2_check.gd`'s new `at_once` exceptions still catch a real regression, or could they hide one?**
   - **They hide real regressions (BLOCKING, findings #4 and #5).**
     - `at_once` permits `want == 0` on `i == 0` (cold cache) to skip stand-in contrast, shared-shader, and `planet_pending` checks, which would pass a synchronous main-thread cold R01 load.
     - Changing the 21 s freeze test to `seed 27` (baked ice) makes it vacuous in headless CI (`compute = false` -> `a == null` returns at `world_planet.gd:124` before `planet_frozen` at line 125 is ever reached).
     - Changing the rebuild test to `seed 26` + `planet_code == "BAKE2"` checks metadata set synchronously at `world_planet.gd:107` before any `await`, so deleting `if built == gen:` at `board.gd:1104` still passes.
     - Lines 259-278 still pass even if the 1-frame wait removed by `69563a9d` is re-introduced. All three regressions were injected into a throwaway copy and still passed their respective checks in headless Godot 4.7.2.
4. **Anything else in the PR diff against `main` that a cold Windows launch would trip on?**
   - **`git merge-tree --write-tree origin/main 69563a9d`:** clean merge (0 conflicts). `planet_v2_check.gd` and `bake_cache_cap_check.gd` both pass (exit 0) in headless Godot 4.7.2 on a fresh throwaway `APPDATA`.
   - **`height_float(4096x2048)` CPU cost (finding #6):** an 8.39M-iteration GDScript loop runs on the serial worker for every cold AND warm-disk load of terran/ice/volcanic relief, taking **1,624 ms** (`+ 25 ms` mipmaps = **1,649 ms**) on this Windows PC.
   - **Misleading `[planet]` load timing log (finding #7):** `battle.gd:803-804` awaits `world.wait_ready()` before `board.wait_planet()`, so `board.gd:1119` logs the world's wait time rather than when the board planet finished.

## Recommended Next Step

Hold PR #1776 for one targeted fix commit addressing the four blocking issues before re-running PC proof: (1) purge abandoned queued jobs (including stale `urgent` jobs from `showcase`/prior battles) before starting a real battle, (2) keep cached images pinned/returned across `request_*()` -> `result()` so FIFO eviction at `CACHE_MAX = 24` cannot return `null`, (3) remove synchronous `_pending.free()` in `world_bake.gd:clear_static()` while `add_child.call_deferred(node)` is queued, and (4) tighten `planet_v2_check.gd` so cold R01, baked/R01 freeze, rebuild `built == gen`, and board-before-sky queue order are all genuinely enforced in headless CI.
